# 録音とメディアプレイヤーの実機確認の手順

この文書は、録音とメディアプレイヤー（Issue #28、`docs/adr/0031-recording-and-playback-nodes.md`、`docs/adr/0043-recording-and-media-player.md`）を Windows の実機で確かめるための手順書です。
CI では、`pa-engine` の単体テストで次のことを確かめています。

- ディスクの書き込みが止まっても、ディスクがいっぱいになっても、オーディオスレッドが待たないこと
- 欠落したぶんが無音で埋まり、トラックの長さがそろうこと
- ストリップはプリフェーダー、Master とバスはポストフェーダーで録ること
- 先読みが遅れても再生がオーディオスレッドを待たせないこと

フェイクの書き出し先を使っています。
JUCE による WAV と FLAC の読み書き（`media`）の単体テストは、Windows の CI で動きます。
この手順書では、CI で確かめられない部分を対象にします。

- 実際のディスクの負荷と容量不足のときに、ライブの音声が途切れないこと
- 異常終了の後にファイルを開けること
- 録ったファイルを DAW で開いたときに長さと時間軸がそろうこと
- 画面の操作

仕様書の Beta2 の合格条件「録音中のディスク負荷や容量不足でライブ音声を止めないこと」は、この確認が終わるまで未達のままです。

## 1. 準備

### 1.1 機材

| 名前 | 役割 | 条件 |
| --- | --- | --- |
| PC-A | 親機（`remote-pa` の親機モードと `pa-engine`） | Windows 11 x64。出力デバイスを 1 台つなぐ |
| PC-B | 子機（`remote-pa` の子機モード）。録る対象のストリップを作る | 同じ LAN。マイクかアプリ音声を送れる状態にする |
| USB-S | 容量の小さい USB メモリ（例: 1 GB）か、小さく作った VHDX | 3.4 で、保存先をいっぱいにするため |

### 1.2 確認用の道具

| 道具 | 用途 |
| --- | --- |
| DAW か Audacity | 録ったファイルを並べて開き、長さ、時間軸、チャンネル数、ビット深度を見る |
| `diskspd`（Microsoft）か、大きなファイルのコピー | 3.3 で、録音中の保存先に読み書きの負荷をかける |
| PC-A の出力の録音（別の PC の録音機に入れる） | ライブの音声が途切れていないことを波形で残す |
| テスト音（子機から送る正弦波かクリック音） | 途切れと欠落を波形で見つけやすくする |

### 1.3 記録すること

- 確認する main のコミット（`git rev-parse --short HEAD`）。すべての証拠にこの値を付ける
- 保存先フォルダのパスと、そのドライブの種類（SSD、HDD、USB メモリ）
- 試験ごとの画面のキャプチャ（録音の区画の状態、経過時間、欠落の警告、直前の結果）、通知の履歴、`<data-dir>\logs` のログ

## 2. 設定

1. ミキサー画面のツールバーの「録音・再生」を押し、メディアの窓を開く。
2. 録音の区画で、保存先フォルダがミュージックの下の `VOCROZ` になっていることを確かめる。
3. 子機を承認して、ストリップを 1 本以上作る。ルーティングで USER のバスを 1 本作って適用する。

## 3. 試験

### 3.1 初期状態

1. `pa-engine` と `remote-pa` を起動し直し、メディアの窓を開く。
2. 録音の区画が「録音していません」で、プレイヤーにファイルが読み込まれていないことを確かめる。
3. 一覧のファイルを選んで読み込み、再生を押すまで音が出ないことを確かめる。

合格: 2 と 3 のとおり（初期ミュート）。
証拠: 画面のキャプチャ、PC-A の出力の録音。

### 3.2 マルチトラックの録音

1. 録る対象に Master、ストリップ 1 本、バス 1 本を選び、形式を WAV にして「録音開始」を押す。
2. 録音中に、ストリップのフェーダーを下げる、ミュートする、バスのフェーダーを動かす。
3. 1 分ほど録って「録音停止」を押す。
4. プレイヤーの一覧に、テイクのフォルダ（`YYYYMMDD-HHMMSS`）の 3 つのファイルが加わることを確かめる。
5. 3 つのファイルを DAW で並べて開く。
6. 形式を FLAC にして、1〜5 を繰り返す。

合格:

- 3 つのファイルの長さがサンプル単位で一致する。
- Master は 2 チャンネル、ストリップは子機の入力のチャンネル数になる。
- 48 kHz、24 bit で記録されている。
- ストリップのファイルには 2 のフェーダーとミュートの操作が入っていない（プリフェーダー）。
- Master とバスのファイルには 2 の操作が入っている（ポストフェーダー）。
- 録音中も録音後も、PC-A の出力が途切れない。

証拠: DAW の画面のキャプチャ（波形と長さ、ファイルの情報）、PC-A の出力の録音。

### 3.3 ディスクの負荷

1. 3.2 と同じ対象で録音を始める。
2. 保存先と同じドライブに、`diskspd`（例: `diskspd -c4G -d120 -w50 -t4 -o32 -b1M test.dat`）で 2 分ほど読み書きの負荷をかける。
3. 負荷を止めてから録音を止める。
4. 画面に欠落の警告が出たかを記録する。DAW で、警告が出たトラックの欠落の位置（無音）と、ほかのトラックとの時間軸を見る。

合格:

- 負荷の間も PC-A の出力が途切れない。
- 欠落があったときは、警告に出た長さと DAW の無音の長さがおおむね一致する。
- 欠落のあったトラックも、ほかのトラックと長さがそろっている。

証拠: PC-A の出力の録音、画面のキャプチャ、DAW の画面のキャプチャ、`diskspd` の出力。

### 3.4 容量不足

1. 保存先フォルダを USB-S の上のフォルダに変える（「変更」を押す）。
2. USB-S の空きが数十 MB になるまで、ほかのファイルで埋める。
3. 「録音開始」を押す。始められないこと、直前の結果に「空き容量が足りない」旨が出ることを確かめる。
4. 空きを 200 MB ほどに戻して録音を始め、空きがなくなるまで録り続ける。
5. 録音が止まり、「録音を止めました。ライブの音声は流れ続けています」の通知が出ることを確かめる。
6. 録れたファイルを DAW で開く。
7. 保存先フォルダを空にして「変更」を押し、既定の場所に戻ることを確かめる。

合格:

- 3 で始まらず、ファイルが残らない。
- 4〜5 の間、PC-A の出力が途切れない。
- 6 で、止まるまでに録れたぶんを再生できる。
- 7 で既定の場所に戻る。

証拠: 画面のキャプチャ、通知の履歴、PC-A の出力の録音、DAW の画面のキャプチャ。

### 3.5 異常終了の後のファイル

1. WAV で録音を始め、30 秒ほど録る。
2. タスクマネージャーで `pa-engine.exe` を強制終了する。
3. 残ったファイルを DAW で開く。
4. FLAC で 1〜3 を繰り返す。

合格:

- WAV は、強制終了の直前の 1 秒までを再生できる（ヘッダーは 1 秒ごとに書き直している）。
- FLAC は、書けたところまでを再生できる。

証拠: DAW の画面のキャプチャ（長さ）。

### 3.6 メディアプレイヤー

1. 一覧から 3.2 で録った Master のファイルと、44.1 kHz の WAV、FLAC、AIFF、Ogg Vorbis のファイルを順に読み込み、再生する。
2. 再生中にシークバーを動かし、その位置から鳴ることを確かめる。停止を押すと先頭に戻ることを確かめる。
3. ファイルの終わりまで再生し、止まって先頭に戻ることを確かめる。
4. 流す先をバスに変え、バスのフェーダーで音量が変わることを確かめる。
5. 再生中に、流す先のバスをルーティングで消して適用する。再生が一時停止し、「流す先のバスがなくなった」旨の通知が出ることを確かめる。Master へ切り替わって鳴り続けないことを確かめる。
6. 再生中に、エクスプローラーで再生中のファイルを USB-S ごと取り外す（保存先が USB-S のとき）。再生が一時停止し、通知が出ることを確かめる。

合格: 1〜6 のとおり。44.1 kHz のファイルの音の高さが変わらない。どの操作でも PC-A の出力にクリックやノイズが出ない（シークと停止は 10 ms のフェードを通る）。
証拠: PC-A の出力の録音、画面のキャプチャ、通知の履歴。

### 3.7 設定の保存

1. 形式、保存先フォルダ、録る対象（Master とバス、ストリップ）を設定する。
2. `pa-engine` と `remote-pa` を終了し、起動し直す。
3. メディアの窓を開き、形式と保存先フォルダ、録る対象の Master とバスが戻ることを確かめる。ストリップは戻らない（セッションごとに振り直すため）。

合格: 3 のとおり。
証拠: 1 と 3 の画面のキャプチャ。

## 4. 結果の報告

試験ごとの合否と証拠のファイル名を Issue #28 にコメントで残します。
不合格の試験があれば、ドライブの種類、保存先、再現の手順を書いた不具合の Issue を立てます。
