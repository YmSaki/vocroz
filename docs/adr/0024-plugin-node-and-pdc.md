# 0024. プラグインノードの形と、プラグイン遅延補正（PDC）の規則

- 状態: 採用（2026-11-08）

## コンテキスト

Beta4 では、チャンネルやバスに VST3 のエフェクトを挿せるようにする（B4、Issue #29）。Beta5 の VSTi はこの上に乗る。
置き場所は ADR-0009 で決めた（グラフ、プラグインノード、PDC は `audio-core`、JUCE による実装は `plugin-host`、挿入位置の判断は `session`）。
この ADR では、ADR-0018 のルーティンググラフにプラグインをどう組み込むか、PDC をどの規則で計算するか、プラグインの処理が失敗したときにどう振る舞うかを決める。

前提は次のとおり。

- 低レイテンシが必須要件で、PDC で遅延を足すのは必要な経路だけにする（ADR-0009）。
- プラグインの処理はオーディオスレッドで呼ぶので、第 9 節のリアルタイム制約に従う。プラグインの中身は保証できないので、失敗を想定する。
- B5 の VSTi は音声入力を持たず、MIDI を受け取って音声を出す。B4 の段階でノードの形を合わせておけば、B5 でグラフの規則を変えずに済む。

## 決定

### ポートとノード

- `audio-core` にポート `PluginProcessor` を定義する。`layout()`（入出力のチャンネル数）と `latency_samples()` はコントロールスレッドから、`process()` はオーディオスレッドから呼ぶ。`process()` は `noexcept VOCROZ_NONBLOCKING` で、結果を `PluginProcessStatus`（`kOk` / `kFailed`）で返す。
- 処理の準備（サンプルレート、ブロック長、チャンネル数）は実装側の責任とし、グラフに渡す前に `kSampleRate` と `kBlockSize` で済ませておく。JUCE の `prepareToPlay()` はメッセージスレッドで呼ぶ必要があり、グラフの構築（任意のコントロールスレッド）とは呼ぶスレッドが違うため。
- ノードの種類 `NodeKind::kPlugin` を加える。`NodeSpec::make_plugin()` は、その時点の `layout()` と `latency_samples()` を記述に写す。グラフの検証と PDC は記述だけから決まる純粋関数のままにするため。プラグインが遅延を変えたら、`session` が記述し直して適用する。
- チャンネル数は入力 0〜2、出力 1〜2。入力 0 は VSTi で、音声の結線を受け付けない（`kInvalidConnection`）。バッファは入力と出力の多い方の本数を確保し、その場で書き換える（JUCE の `AudioBuffer` と同じ形）。モノラルの入力はステレオの入力へ複製し、ステレオからモノラルへのダウンミックスは既存の規則どおり受け付けない（`kChannelMismatch`）。
- `process()` に、ブロック内の MIDI イベント（値型 `MidiEvent`）の範囲を渡す。B4 では常に空で、B5 がタイムスタンプからサンプルオフセットへの変換と合わせて埋める。
- 挿入は結線の間にノードを置いて表す。チャンネルストリップへの挿入は「ソース → プラグイン → ストリップ」で、手動ディレイ、プリフェーダーのメーター、フェーダーの前に入る。バスへの挿入は「バス → プラグイン → 後段」。ストリップやバスの中にスロットを持たせる方式は、ノードの種類ごとに処理の分岐が増え、PDC の経路の計算も別に書くことになるので採らない。
- プラグインはフェーダーを持たないので、プリフェーダーのセンドの送り元にはできない（`kInvalidSendTap`）。

### PDC

- 遅延に数えるのは、プラグインが報告する処理の遅延だけにする。ストリップの手動ディレイ（同期のための意図した遅延）と遅延ノード（演出の遅延）は数えない。数えると、PDC が意図した時間差を打ち消すため。
- 処理順に沿って、各ノードの出力の遅延を「入力の遅延の最大値 + 自分の遅延」で求める。合流するノードでは、遅延の少ない入力の結線にだけ差の分の遅延を足す。合流しない経路（別の出力へ向かう経路）には足さず、低遅延を保つ。複数の出力ノードの間もそろえない。
- 遅延ノードへ入る結線（フィードバック経路）は補正しない。遅延ノードの出力は 0 から数え直す。ループの時間はオペレーターが遅延ノードで決めたものなので、PDC で変えない。
- 経路の遅延の上限を `kMaxLatencyCompensationSamples`（1 秒）にし、超える記述は `kLatencyOutOfRange` で拒否する。経路の遅延を抑えれば補正（経路の差）も上限以下に収まり、補正のディレイラインのメモリが上限で決まる。
- 補正は結線ごとのディレイライン（送り元のチャンネルごとに 1 本）で行い、グラフの構築時に確保する。センドレベルより前に掛ける。
- 計算結果は `analyze_latency()` で公開し、`session` と画面がステージング中にグラフ全体の遅延を示せるようにする。

### 失敗の扱い

- `process()` が `kFailed` を返すか、出力に NaN か無限大が含まれたら、そのノードの出力を無音にし、そのグラフを破棄するまで以降のブロックもプラグインを呼ばずに無音にする。
- 素通し（バイパス）ではなく無音にするのは、フェイルセーフ（AGENTS.md 1.2）に従うため。プラグインで下げていた音量（コンプレッサーやゲイン）が突然戻ると、本番中に過大な音が出る。
- 失敗をオペレーターに知らせる経路は、`session` との接続（S1 の後）で加える。`plugin-host` の実装も、プラグインの例外を捕まえたら以降は `kFailed` を返し続ける。

## 理由

- プラグインを独立したノードにすれば、PDC は「ノードの遅延」だけを見る 1 つの規則で済み、ストリップ、バス、センドのどの経路にも同じ計算が働く。
- 記述に遅延とチャンネル数を写しておけば、検証と PDC を OS も JUCE もなしに単体テストでき、RealtimeSanitizer でプラグインノードの処理を検査できる。
- 合流点だけを補正する方式は、全経路を最大遅延にそろえる方式（DAW の全体補正）より、プラグインを挿していない経路の遅延が増えない。合奏の返送モニターでは、この差が演奏のしやすさに直結する。

## 結果

- B4 の残り（`plugin-host` の JUCE による実装、`pa-plugin-scanner`、エディターのウィンドウ、状態の保存）は、このポートを実装する。`session` のポート（`PluginLoader`、`PluginScanner`、`PluginEditorHost`）は、S1 で `session` ができた後に加える。
- B5 は `MidiEvent` に変換とルーティングを加え、入力 0 のプラグインノードとして VSTi を置く。グラフの検証規則と PDC は変えない。
- プラグインの遅延が変わるたびにグラフを差し替えるので、変更の頻度が高いプラグインではスワップが増える。問題になれば、`session` 側で変更をまとめてから適用する。
