# 0022. セッション管理の分担、子機と親機の制御メッセージ、再接続トークンと招待の扱い

- 状態: 採用（2026-11-08）

## コンテキスト

`session` は、招待、承認、再接続、参加者とチャンネルストリップの状態、コマンドの適用を受け持つ（AGENTS.md 3.3）。
仕様書は状態の正規名と遷移条件を定めているが、実装に必要な次の点は決まっていなかった。

- `session` と、接続を実際に張る `transport`・`network`・コンポジションルートの境目。
- 子機と親機の間の制御メッセージ（参加の申請、承認、ミュートの通知など）の形式。ADR-0019 は、信頼制御層の上で運ぶ本文の形式を使う側（`session`）が決めるとした。
- 再接続トークンの寿命。計画の段階で「セッションの終了かストリップの削除まで有効で、`LOST` からも同じストリップへ戻れる」と決めたが、子機が 120 秒であきらめた後にどう戻るかは決めていない。
- 招待の期限（30 分）が来たときの振る舞いと、親機での招待の照合。
- 親機の entity ごとの revision の進め方（ADR-0015 は子機と観測値の規則までを決めた）。

## 決定

### 分担

- `session` は親機の `HostSession` と子機の `ClientSession` を公開し、どちらもコントロールスレッドからだけ呼ぶ。状態機械（`SessionState`、`ConnectionState`、`OutputDeviceState`、`ClientState`）は `src/state/` の遷移表に置く。
- 外部への作用はすべてポートで行う。親機は `MixerControl`、`PeerLink`、子機は `CaptureControl`、`HostLink`、両方が `RendezvousClient`、`SettingsStore`、`UiEventSink` を使い、親機はトークンの生成に `SecureRandom` も使う。`SecureRandom` の実装はコンポジションルートが `transport` の乱数（libsodium）で用意する。
- 経路の確立（直結、ホールパンチ）と Noise_IK の鍵交換は `session` から 1 つの操作に見せる。子機は `HostLink::connect()` を呼び、終わったら `on_link_established()` を受け取る。親機は接続ごとの識別子 `PeerHandle` で子機を区別し、`PeerHandle` は組み立て側が振る。
- 参加の申請は、暗号化された経路の上で送る。承認前の接続のメディアは受け付けず、承認したら `PeerLink::admit()` でストリップのチャンネルへ流し始める。承認後の `CONNECTING` から `CONNECTED` への遷移は、組み立て側がメディアの受け付けの準備ができたときに `on_peer_established()`（子機は `on_media_established()`）で知らせる。

### 制御メッセージ

- 形式は `modules/session/src/wire/peer_message_codec` に置く。先頭 1 バイトが種別、続いて種別ごとのフィールドで、整数はビッグエンディアン、文字列は長さ 1 バイトと UTF-8 の本体。余分なバイト、0 と 1 以外の真偽値、表示できない文字列（不正な UTF-8、制御文字）は不正とする。
- 子機から親機は `JOIN_REQUEST`（0x01）、`RECONNECT_REQUEST`（0x02）、`SEND_MUTE`（0x03、ミュートと世代番号）、`INPUT_STATUS`（0x04）、`LEAVE`（0x05）。親機から子機は `JOIN_PENDING`（0x81）、`JOIN_APPROVED`（0x82、再接続トークン）、`JOIN_DENIED`（0x83、理由）、`SESSION_ENDED`（0x84）。
- デコーダーは向きごとに分け、受け取る側の向きの種別だけを受け付ける。子機から親機へ送れるのは参加の申請と自分の状態の通知だけで、Master や他のチャンネルを操作する種別はない。改変された子機が未知の種別を送っても捨てるだけで、状態は変わらない。
- 子機の送信ミュートの通知は、親機のチャンネルミュートを変えない。親機は通知を `PeerLink::apply_send_mute()` でメディアの受信側（信号状態の判定）へ渡す。

### 再接続トークン

- 承認時に親機が 256 bit の乱数で発行し、`JOIN_APPROVED` で渡す。セッションの終了かストリップの削除まで有効で、`RECONNECTING`、`LOST`、`FAILED` のどこからでも、承認なしで同じストリップへ戻れる。
- 子機は回線の途絶後、`RECONNECT_REQUEST` で戻る。120 秒戻れなければ `RECONNECT_TIMEOUT` で `FAILED` にするが、トークンは捨てない。同じ親機（同じ静的公開鍵）の招待で参加し直すと、`JOIN_REQUEST` にトークンを添え、`LOST` のストリップへ戻る。
- 子機は、`REJECTED`、`RECONNECT_TIMEOUT`、`SESSION_ENDED` のいずれかの理由で申請を拒否されたときと、`SESSION_ENDED` の通知を受け取ったときにトークンを捨てる。トークンはメモリにだけ置き、設定ファイルやログに書かない。

### 招待

- 招待トークンは 256 bit の乱数で、親機が作ってランデブーサーバーに預ける。期限は親機でも数え、子機の申請に添えられた招待トークンを親機自身が照合する。期限切れは `INVITE_EXPIRED`、取り消し済みは `INVITE_REVOKED`、知らないものは `INVITE_INVALID` で拒否する。理由を区別するため、最近の 16 件を覚えておく。
- 期限が来たら、親機は新しい招待を自動で発行し、表示する招待 URL を差し替える。発行に失敗したら 10 秒おいて再試行する。手動の失効（`HostSession::revoke_invite()`）も、失効させてから新しい招待を発行する。
- セッションの終了時は招待を失効させ、終了後に届いた登録の結果もすぐに失効させる。

### コマンドと revision

- コマンドごとに対象にできる entity の種類を決め、それ以外は `INVALID_STATE` で拒否する。親機は子機のコマンド（`join` など）を、子機は親機のコマンドを受け付けない。
- セッションの entity の revision は、`create_session` と `end_session` を適用したときに進める。`READY` と `ACTIVE` の切り替え、出力デバイスの状態、招待 URL の差し替えは観測値として進めない。
- Master の revision は、ミュートの値か理由が変わったときに進める。エンジンが `SAFETY` でミュートした場合も進める（ADR-0015）。
- 承認待ちの entity にはコマンドで変える値がないので、revision は 1 のまま進めない。承認と拒否の `ack` はその revision を返す。
- `remove_strip` は `LOST` と `FAILED` のストリップにだけ適用する。音を出しうるストリップを消さないため。
- 子機の退出（`LEAVE`）と接続の終了は、猶予を待たずに `LOST` にする。

### 上限

承認待ちは 16 件、ストリップは 64 本、表示名は 64 バイト、セッション名は 128 バイト、重複を見分ける `request_id` は直近 256 件。どれも `modules/session/src/session_constants.h` に根拠と一緒に置く。

## 理由

- 経路の確立と鍵交換を 1 つの操作に見せると、`session` は NAT 越えの方式や Noise の手順を知らずに、状態の規則だけを持てる。`network` と `transport` の組み合わせ方は E1 と E2 のコンポジションルートで変えられる。
- 申請を暗号化された経路の上で送ると、ランデブーサーバーがメッセージを中継しない（ADR-0012）まま申請を届けられ、子機の静的鍵も鍵交換で確かめられる。メディアは承認まで受け付けないので、承認前の遮断の要件は保たれる。
- 子機が 120 秒であきらめた後もトークンを残すと、仕様の「子機は猶予切れで `FAILED`」と、計画の「`LOST` からも同じストリップへ戻る」を両立できる。参加し直すだけで元のストリップに戻り、チャンネルが増えない。
- 招待を親機でも照合するのは、認可をエンジンで行うため（AGENTS.md 6.3）。ランデブーサーバーの失効の要求が届かなかった場合でも、取り消した招待では入れない。
- 期限切れのたびにオペレーターが招待を作り直すのは本番中の負担になるので、自動で差し替える。表示中のコードが変わるだけで、参加済みの子機には影響しない。

## 結果

- E1（`pa-engine`）と E2（子機モード）のコンポジションルートは、`HostSession` と `ClientSession` のポートを `audio-core`、`transport`、`network`、`capture`、`persistence` で実装し、ネットワーク受信スレッドとデバイスからの通知をコントロールスレッドへ移して渡す。`tick()` は 100 ms〜1 s の間隔で呼ぶ。
- 制御メッセージの形式を変えるときは、`session` の `src/wire/` を変更し、互換のない変更なら ADR-0014 のプロトコルバージョンを上げる。
- 未対応で後続に残すもの: 親機のストリップの「入力なし」の表示（`ChannelStrip` に欄がないため、`session` は状態を保持するだけ）、招待の手動の失効と出力デバイスの選択の UI コマンド、子機の表示名を設定する画面。どれも `control-protocol` のメッセージの追加が必要になる。
