# 0027. 設定、ログ、秘密情報の保存の形と置き場所

- 状態: 採用（2026-11-08）

## コンテキスト

`persistence` は、設定のアトミックな保存、ログファイルへの出力、秘密情報の保護を受け持つアダプターである（AGENTS.md 3.3）。
仕様書は、一時ファイル → fsync → リネームによる保存、1 世代のバックアップ、破損時の全ミュートでの起動とバックアップからの復元、10MB × 5 程度のローテーション、マスキング済みの診断レポート、DPAPI か資格情報マネージャーによる秘密情報の保護を求めている。
実装に必要な次の点は決まっていなかった。

- 設定ファイルの名前と分け方。仕様書の保存先（`%LOCALAPPDATA%/RemotePAConsole/settings.json`）は、ADR-0007 で `--data-dir`（既定 `%LOCALAPPDATA%\VOCROZ\`）に変わっている。親機モードと子機モードは同じ `--data-dir` で同時に動ける（ADR-0007 の単一インスタンスの範囲）。
- 破損したときに、バックアップから自動で読むか、利用者に復元を選ばせるか。
- 秘密情報を DPAPI と資格情報マネージャーのどちらで守るか。秘密情報を読み書きするポートもまだない。
- ログと診断レポートで、何をどう伏せるか。
- fsync とアトミックな名前の置き換えは OS の API でしか書けないが、保存の規則は Linux の CI で単体テストしたい。

## 決定

### 置き場所

`--data-dir` の下に次の形で置く。インストールフォルダには書かない。

| パス | 内容 |
| --- | --- |
| `host-settings.json`（`.bak`、書き込み中は `.tmp`） | 親機の設定（`pa-engine` が書く） |
| `client-settings.json`（同上） | 子機の設定（`remote-pa` の子機モードが書く） |
| `logs/<プロセス名>.log`、`<プロセス名>.1.log`〜`.4.log` | ログ。プロセス名はコンポジションルートが決める（例: `pa-engine`、`remote-pa-host`、`remote-pa-client`） |
| `secrets/<種類>.bin` | DPAPI で暗号化した秘密情報 |

設定ファイルをモードごとに分け、2 つのプロセスが同じファイルを書き合わないようにする。ログもプロセスごとにファイルを分ける。

### 設定の保存と読み込み

- 保存は、一時ファイルに書いてディスクまでフラッシュ → 今の本体が正常（パースできる）ならバックアップへ置き換え → 一時ファイルを本体へ置き換え、の順で行う。今の本体が壊れているときはバックアップに回さず、正常なバックアップを壊れた内容で上書きしない。
- 読み込みは、本体 → バックアップの順にパースし、最初に読めたものを使う。バックアップから読んだら警告をログに残す。どちらも読めなければ `SettingsError::kCorrupted` を返し、`session` が既定値で起動する。どちらもなければ `kNotFound`（初回の起動）。
- 仕様書の「破損時は安全な初期状態で起動し、バックアップからの復元ボタンを提示する」は、復元ボタンを作らず、バックアップから自動で読む形に変える。設定にはミュートの状態を保存しない（`vocroz/session/settings.h`）ので、バックアップから戻しても起動は必ず全ミュートから始まり、「再起動直後にいきなり音が出ない」要件は変わらない。復元のために画面とコマンドを足すより、利用者の操作が 1 つ減る。
- 設定ファイルは `schema_version`（今は 1）を持つ JSON にする。型、必須のフィールド、形式のバージョンが合わなければ壊れているとみなす。値の範囲（フェーダーの範囲、名前の長さ）は `session` が起動時に直すので、`persistence` では検査しない。

### 秘密情報

- `session` に `SecretStore` ポート（`load`、`save`、`erase`、種類は `SecretSlot`）を足す。親機と子機の Noise の静的秘密鍵を、再起動しても同じ鍵で使い続けるために使う。使うのは E1 と E2 のコンポジションルートで、`transport` の `StaticKeyPair` に渡す。`persistence` は `transport` に依存できないので、ポートは `session` に置く。
- 実装は、DPAPI（`CryptProtectData`、現在のユーザーの範囲）で暗号化したファイルを `secrets/` にアトミックに保存する形にする。資格情報マネージャーは使わない。DPAPI のエントロピーには種類の名前を入れ、別の種類のファイルに置き換えられても復号に失敗するようにする。バックアップは作らない。
- 暗号化は `persistence` の中だけの `DataProtector` に分け、ファイルの扱い（`SecretFileStore`）は Linux の CI でフェイクを使って単体テストする。DPAPI の実装は Windows の CI でだけテストする。

### ログ

- 1 件を 1 行にし、`<UTC の時刻（ミリ秒）> [<重要度>] <メッセージ>` の形で書く。メッセージの改行などの制御文字は空白にして、偽の行を作れないようにする。
- 1 ファイルの上限（既定 10MB）を超えそうになったら、`.log` → `.1.log` → … とずらし、残すのは既定 5 ファイル。1 件ごとに OS へ渡すが、ディスクへの同期まではしない（強制終了の直前のログを残しつつ、ログで処理を遅らせないため）。
- `--log-level` より低い重要度は書かない。フォルダを作れないなどで書けなくても、起動は止めず黙って捨てる（`Logger` の契約）。

### 伏せる規則

書く側はログに秘密情報を入れない（AGENTS.md 6.4）。そのうえで、ログファイルに書く直前と診断レポートを作るときに、同じ規則でもう一度伏せる（`mask_sensitive_text()`）。

| 対象 | 見分け方 | 置き換え |
| --- | --- | --- |
| 鍵、トークン | 英数字（`_`、`-` を含む）が 32 文字以上続き、数字を含む | `<secret>` |
| 招待コード | Crockford Base32 の正規の大文字 10 文字か、5 文字 + `-` + 5 文字 | `<invite-code>` |
| IP アドレス | グローバルな IPv4（LAN、ループバック、リンクローカル、CGNAT は残す） | `<ip>` |
| ユーザー名 | パスの `\Users\<名前>\`、`/Users/<名前>/` | `<user>` |

表示名とセッション名は形から見分けられないので、診断レポートでは設定の値ごと `<masked>` にする（空なら空のまま）。

### 診断レポート

`write_diagnostic_report()` が、作成時刻、バージョン、環境の説明、親機と子機の設定（名前を伏せた JSON か、壊れている、ない、の説明）、ログ（新しいものから合計 8MiB まで、古い順に並べる）を 1 つの UTF-8 のテキストに書く。呼び出す画面とコマンドは E1 と UI の作業で足す。

### OS ごとの実装の置き場所

ディスクまでのフラッシュとアトミックな名前の置き換えだけを `src/detail/durable_io.h` の 2 つの関数にし、`src/win/`（`FlushFileBuffers`、`MoveFileExW` の `MOVEFILE_WRITE_THROUGH`）と `src/posix/`（`fsync`、`rename`、親フォルダの `fsync`）に実装を置く。`src/posix/` は AGENTS.md 5.3 の構成にないディレクトリで、製品には入らない。Linux の CI で保存の規則を実際のファイルでテストするための例外として、この ADR で認める。

## 理由

- 自動でバックアップから読むと、全ミュートの要件を保ったまま、利用者の操作と UI の実装を減らせる。UX を損なわない範囲で実装しやすい方法を選ぶ方針（2026-11-07）にも合う。
- 秘密情報を `--data-dir` の下に置くと、同じ PC の親機と子機（別の `--data-dir`）が別の鍵を持ち、アンインストールの完全削除でフォルダごと消える。資格情報マネージャーではユーザー全体で共有される名前の管理と、削除の漏れの対策が別に要る。
- DPAPI は Windows の現在のユーザーの範囲で鍵を管理し、鍵の保存を自作せずに済む。
- 伏せる規則を 1 か所に置くと、ログと診断レポートで規則がずれない。ログは 1 件ごとに通るので、`std::regex` を使わず 1 回の走査で判定する。
- OS の差を 2 つの関数に閉じ込めると、アトミックな保存の順序（`AtomicFile`）と読み込みの規則（`JsonSettingsStore`）を OS なしにテストできる。

## 結果

- 書き込み途中の中断（一時ファイルだけが新しい、本体がない）、本体の破損、本体とバックアップの両方の破損で、バックアップか既定値で起動し、`HostSession` と `ClientSession` が全ミュートで始まることを単体テストで確かめる。
- E1（`pa-engine`）と E2（子機モード）のコンポジションルートは、`make_rotating_file_logger()`、`make_json_settings_store()`、`make_dpapi_secret_store()` で作ったものを注入する。静的鍵は `SecretStore::load()` が `kNotFound` か `kCorrupted` なら作り直して保存する。
- 診断レポートの出力先の選択と、出力を呼ぶ画面とコマンドは未実装。`control-protocol` にコマンドを足すのは E1 と UI の作業。
- 仕様書の保存先とファイル名（`settings.json`、`sessions/`、`cache/`、`updates/`）は、この ADR と ADR-0007 に合わせて読み替える。`sessions/`、`cache/`、`updates/` はそれを使う作業で決める。
- `pa-updater` の設定のバックアップ（`apps/updater/src/win/file_settings_backup.cpp`）は、まだ `settings.json` という 1 つのファイルを退避している。この ADR のファイル名（`host-settings.json`、`client-settings.json`）を退避するよう、続きの PR で直す。ファイル名の知識は `persistence` の公開ヘッダーから取る形にする。
- IPv6 アドレスと、メールアドレスのような個人情報は伏せない。ログに書かないことで守る。
