# 0043. 録音とメディアプレイヤーの状態、ファイル、ディスク I/O スレッド、メディア画面

- 状態: 採用（2026-11-15）

## コンテキスト

ADR-0031 で、録音タップ（`RecordingTrack`）と再生ノード（`PlaybackTrack`）を `audio-core` に置き、ファイルの読み書きを `AudioFileWriter` と `AudioFileReader` のポートの向こうに出した。
B2a（Issue #28）を仕上げるには、次のことを決める必要がある。

- ポートを実装する `media` のファイル形式（WAV、FLAC）、空き容量の扱い、サンプルレートの変換
- 何を録れて、録音をどう始めて止めるか。ファイルをどこに、どんな名前で置くか
- ディスク I/O スレッドを誰が持ち、どう回すか
- 書き込みの失敗（容量不足を含む）と欠落を、どう扱って UI に示すか
- メディアプレイヤーで再生するファイルをどう選び、どのバスへ流すか
- メディア・録音管理の画面

仕様書の Beta2 の合格条件は「録音中のディスク負荷や容量不足でライブ音声を止めないこと」で、ADR-0031 の仕組みでオーディオスレッド側はすでに満たしている。
ここで決めるのは、その外側である。

## 決定

### ファイル形式（`media`）

- `media` は JUCE の `WavAudioFormat` と `FlacAudioFormat` で書き、`AudioFormatManager::registerBasicFormats()` の形式（WAV、AIFF、FLAC、Ogg Vorbis）を読む。FLAC は JUCE に内蔵の libFLAC（BSD-3-Clause）を使い、新しいライブラリは足さない。
- 書き出しの形式は `audio_core::AudioFileFormat`（`kWav`、`kFlac`）で選ぶ。ビット深度はどちらも 24 bit に固定する。マイクの録音で 16 bit では余裕が足りず、32 bit float は FLAC で書けないため、両方で同じにそろえる。サンプルレートは 48 kHz（エンジンのレート）。
- WAV が 4 GiB を超えたら、JUCE が RF64 で書く（48 kHz、24 bit、ステレオで約 4 時間）。
- WAV は、音声の 1 秒ごとに `AudioFormatWriter::flush()` でヘッダーを書き直す。エンジンが異常終了しても、直前の 1 秒までを再生できるファイルとして残すため。FLAC はフレームがそれぞれ独立して読めるので、ヘッダー（総サンプル数）が確定していなくても途中まで読める。
- 空き容量:
  - 書き出しの前に、ボリュームの空きが `kMinFreeDiskBytes`（64 MiB）を下回っていたら `kDiskFull` を返し、そのファイルには以降書かない。空きを 0 まで使い切ると、ヘッダーの書き直しと閉じる処理まで失敗し、録れたぶんも再生できなくなるため。また、OS とほかのアプリの動作に要る空きを残すため。
  - 空きを調べる処理は時間がかかりうるので、書き出した量が `kFreeSpaceCheckBytes`（4 MiB）に達するたびに 1 回だけ調べる。
  - JUCE の書き込みが失敗したときも、空きを調べて `kDiskFull` か `kIoError` に分ける。
- 読み込みは、ファイルのサンプルレートが 48 kHz でなければ JUCE の `ResamplingAudioSource` で 48 kHz に変換する。シークでは変換の状態を捨てて読み直す。3 チャンネル以上のファイルは先頭の 2 チャンネルだけを使う。
- 長さ（`length_frames()`）は 48 kHz に換算したフレーム数で返す。`AudioFileReader` のポートに足す。

### 何を録るか

- 録れるのは、チャンネルストリップ、Master、ルーティングのバス（ADR-0018）。どれも 1 トラック 1 ファイルにする（マルチトラック）。
  - ストリップはプリフェーダー（挿入の後、手動ディレイの後、フェーダーの前）で録る。録音は後でミックスし直すための素材で、本番中のフェーダーやミュートの操作を録音に焼き込まないため。ストリップのミュート中も録れる。
  - Master とバスはポストフェーダー（挿入の後）で録る。配信や記録に出した音そのものを残すため。安全リミッターは通さない（リミッターは出力を守る部品で、記録は後で処理し直せるため）。
- トラックのチャンネル数は、Master とバスは 2、ストリップは録音を始めたときのストリップのチャンネル数（1 か 2）にする。
- 録る対象の一覧は録音の設定（`sources`）として持ち、ストリップの entity_id はセッションごとに振り直すので保存しない（ADR-0033 のセンドと同じ扱い）。
- 録音中に対象がグラフからなくなっても（子機の退出、バスの削除）、録音タップはグラフに残して無音を書き続ける。ほかのトラックと長さをそろえ、時間軸を保つため（ADR-0031 と同じ考え方）。ストリップのチャンネル数が録音中にトラックより増えたときも、つなげないので同じく無音になる。

### 録音の始め方と止め方、ファイルの置き場所

- 録音は entity `recorder` 1 つで表し、状態は `STOPPED` と `RECORDING` の 2 つにする。起動時は `STOPPED`。
- 開始は、設定の `sources` のすべてのトラックのファイルを開いてから、すべての録音タップを 1 つのグラフで足す。1 つでも開けなければ、開いたファイルを消して何も始めない。録音タップは 1 つのグラフで足し外しするので、すべてのトラックが同じサンプルから始まり、同じサンプルで終わる（ADR-0031）。
- 停止は、録音タップを外したグラフを適用し、古いグラフの破棄（`Mixer::is_graph_settled()`）を待ってから、ディスク I/O スレッドで残りを書いてファイルを閉じる。状態は停止のコマンドを受けた時点で `STOPPED` にする。閉じ終わるのを UI に待たせないため。
  - 出力デバイスが開いていないとオーディオスレッドが回らず、古いグラフはいつまでも破棄されない。そのため、外してから `kRecordingFinishTimeout`（1 秒）たったら、落ち着くのを待たずに閉じる。録音タップに書くスレッドがなければ、閉じても競合しないため。
- 録音のファイルはメディアフォルダの下に、開始ごとのフォルダ（テイク）を作って置く。
  - テイクのフォルダの名前は、開始した時刻（ローカル時刻）の `YYYYMMDD-HHMMSS`。同じ名前があれば `-2`、`-3` を付ける。
  - ファイルの名前は `<2 桁の番号>-<表示名>.<拡張子>`（例: `01-Master.wav`、`02-Vocal.flac`）。番号は `sources` の順。表示名はストリップかバスの名前で、Windows でファイル名に使えない文字を `_` に置き換え、80 バイトまでに切り詰める。
- メディアフォルダは設定（`folder`）で変えられる。既定はユーザーの「ミュージック」フォルダの下の `VOCROZ`。録音を止めている間だけ変えられる。
- 形式（`format`）と `folder` は保存し、`sources` のうち Master とバスだけを保存する。`folder` が既定の場所なら空文字列で保存し、ミュージックの場所を移しても既定に追従させる。

### ディスク I/O スレッド

- `pa-engine` が、ディスク I/O スレッドを 1 本持つ（`DiskIoWorker`）。10 ms ごとに、録音中のすべてのトラックの `RecordingTrack::drain()` と、メディアプレイヤーの `PlaybackTrack::fill()` を呼ぶ。
  - 10 ms は、録音のリングバッファ（4 秒）と再生の先読み（2 秒）に対して十分に短く、何もないときに CPU をほとんど使わない周期。
  - トラックの追加と削除はコントロールスレッドから依頼し、一覧の写しを取ってからロックの外で I/O を行う。コントロールスレッドを I/O の遅れで止めないため。
- ファイルを開く処理（テイクのフォルダの作成を含む）は、コントロールスレッドで行う。開けなかった理由を、コマンドの処理の中ですぐに状態（`last_result`）へ載せるため。
- `session` は新しいポート `RecorderControl` と `MediaPlayerControl` を通してだけ録音と再生を操作し、スレッドを知らない。`pa-engine` の `EngineRecorder` と `EngineMediaPlayer` が、ミキサーのグラフ（録音タップと再生ノード）と `DiskIoWorker` を組み立てて実装する。

### 失敗と欠落

- どれか 1 つのトラックの書き出しが失敗したら（容量不足を含む）、録音全体を止め、通知（`recording_failed`）を出す。止めたトラックも、書けたところまでを閉じて残す（ADR-0031）。
  - 録音のファイルはすべて同じフォルダ（同じボリューム）に書くので、1 トラックが容量不足なら、ほかのトラックもすぐに続く。一部のトラックだけが続いた録音は、あとで並べたときに長さがそろわず、使いにくい。
  - ライブの音声は止まらない。録音は外部への出力ではないので、ミュートする側に倒す必要もない。
- 欠落（ADR-0031 の `dropped_frames()`）は、トラックごとに欠落した長さ（ms）として状態に載せ、UI は警告として示す。欠落は無音で埋まっているので、録音は続ける。
- 録音の経過時間と欠落は観測値なので、録音中は 1 秒ごとに `recorder_updated` を出し、revision は進めない（`docs/adr/0015-control-protocol-messages.md` の観測値の規則）。

### メディアプレイヤー

- メディアプレイヤーは entity `media_player` 1 つで、同時に再生するファイルは 1 つにする。BGM や効果音を順に流す用途で、複数を重ねる要望は今はない。
- 再生できるファイルは、メディアフォルダの中の音声ファイル（`.wav`、`.flac`、`.aif`、`.aiff`、`.ogg`）に限る。一覧（ライブラリ）はエンジンが作ってスナップショットに載せ、UI は一覧の相対パスでファイルを選ぶ。
  - 任意のパスを UI から受け取らないので、エンジンが読むファイルをメディアフォルダの中に閉じ込められる。`..` を含むパスとリンクの先は一覧に載らず、一覧にないパスは `NOT_FOUND` で拒否する。
  - 一覧はサブフォルダを 2 段まで（テイクのフォルダを含む）、`kMaxMediaFiles`（128）件までにする。スナップショットを `kMaxMessageBytes`（64 KiB）に収めるため。
  - 一覧はファイルを読み込むとき、録音を止めたとき、UI の求め（`refresh_media_library`）で作り直す。フォルダを監視し続けることはしない。
- 流す先（`target`）は Master かルーティングのバスから選ぶ。既定は Master。再生ノードはフェーダーを持たないので、音量は流す先のフェーダーで決める（ADR-0031）。プレイヤー専用のフェーダーが要るなら、バスを 1 つ作ってそこへ流す。
- 状態は `STOPPED`、`PLAYING`、`PAUSED` の 3 つ。起動時とファイルを読み込んだ直後は `STOPPED` で、再生の操作をするまで鳴らない（初期ミュート）。
  - ファイルの終わりに達したら `STOPPED` にして先頭へ戻す。
  - 停止は一時停止と先頭へのシークで表す（`PlaybackTrack` の 10 ms のフェードを使う）。
- 再生位置は観測値として、再生中は 250 ms ごとに `media_player_updated` を出す（revision は進めない）。シークバーの動きとして十分な細かさで、メッセージを増やしすぎない間隔。
- 流す先がルーティングの適用でなくなったら、再生を一時停止し、通知（`media_player_target_removed`）を出す。別のバスへ暗黙に切り替えない（AGENTS.md 1.2 のフェイルセーフ、ADR-0040 と同じ）。
- ファイルを開けなかったら、コマンドは受け付けたうえで、理由（`NOT_FOUND`、`UNSUPPORTED_FORMAT`、`IO_ERROR`）を `last_result` に載せ、プレイヤーは空のままにする。録音の開始でファイルを開けなかったときも同じく、`STOPPED` のまま `last_result` で知らせる。コマンドの拒否（`reject`）は、ACK を待つ UI がトーストで示すだけで状態に残らないので、画面に理由を残すため。
- 再生中に読み込みが失敗したら、一時停止にして通知（`media_player_failed`）を出す。

### UI とエンジンの間の制御

- `recorder` の状態: 設定（`format`、`folder`、`sources`）、状態、テイクの名前、経過時間（ms）、トラックごとの欠落（ms）、直前の結果（`OK`、`DISK_FULL`、`IO_ERROR`、`FOLDER_UNAVAILABLE`）。
- `media_player` の状態: 読み込んだファイル（相対パス、チャンネル数、長さ）、流す先、状態、再生位置、直前の結果。ライブラリはスナップショットと `media_library_updated` で送る。
- コマンド:
  - `set_recorder_config`（設定の変更。録音中は `INVALID_STATE`）
  - `set_recording`（開始と停止）
  - `load_media`（ファイルの読み込み。空なら外す）
  - `set_media_transport`（`PLAYING`、`PAUSED`、`STOPPED`）
  - `seek_media`（再生位置、ms）
  - `set_media_target`（流す先）
  - `refresh_media_library`
- revision はコマンドで変えた値で進め、観測値（経過時間、欠落、再生位置、ファイルの終わりでの停止）では進めない。
- 失敗の通知（`recording_failed`、`media_player_failed`、`media_player_target_removed`）は、既存の `notice` イベントで送る。新しいイベントは作らない。

### メディア画面

- メディア・録音管理の画面は、ルーティング画面と同じく別の窓で開く（ADR-0038）。初期化データの `screen` は `media`、request_id の接頭辞は `md`。窓を開く求めは `vocroz.window` の `open_media`。
- ミキサーの窓のツールバーの「録音・再生」ボタン（これまで開発中の表示だったもの）で開く。ブラウザでの開発時は同じ窓で画面を切り替える。
- 画面は録音（形式、フォルダ、録る対象の選択、開始と停止、経過時間、欠落の警告）とプレイヤー（ライブラリ、流す先、再生、一時停止、停止、シークバー）の 2 つの区画にする。
- 2 つの窓が同じ entity を操作することはない。録音とプレイヤーの操作はメディアの窓だけにあり、ADR-0038 の「窓ごとに entity が重ならない」前提を保つ。

## 理由

- **ライブ音声を止めない**: オーディオスレッド側は ADR-0031 のリングバッファと欠落の記録で守られている。この ADR では、ファイルを開く処理（コントロールスレッド）と書き出し（ディスク I/O スレッド）を分け、どちらもオーディオスレッドから呼ばないことで、ディスクの不調がオーディオに届かないようにする。
- **録った素材を失わない**: 1 秒ごとのヘッダーの書き直しと、空き容量の下限で、異常終了や容量不足のときにも録れたところまでを再生できる形で残す。
- **テスタビリティ**: `session` は `RecorderControl` と `MediaPlayerControl` のポートだけを見るので、開けない、容量不足、欠落、ファイルの終わりをフェイクで再現できる。`pa-engine` の組み立ても、`media` の代わりに `audio-core` のフェイク（`FakeAudioFileWriter` の遅延と容量不足）を使って Linux の CI でテストする。
- **ファイルの選択を一覧に限る**: WebView の中では OS のファイル選択のダイアログを開けず、ネイティブ側に新しい窓の経路を足すと UI の窓と同じ数の考慮（モーダル、ハング）が要る。メディアフォルダの一覧から選ぶ形なら、新しい経路なしに、読めるファイルの範囲もエンジンで決められる。録音したテイクをそのまま再生して確かめることもできる。

## 結果

- 新しいモジュール `media` を `modules/media` に作る（ADR-0009 と AGENTS.md の表には既にある）。JUCE を使うので、`VOCROZ_WITH_JUCE` が ON のときだけビルドし、単体テストは Windows の CI で動く。
- `audio-core` に `AudioFileFormat` と `AudioFileReader::length_frames()` が加わる。
- `media` のファクトリー関数は、AGENTS.md 5.1 の形式に合わせて `make_audio_file_writer()` と `make_audio_file_reader()` にする。
- `session` に `RecorderControl` と `MediaPlayerControl` と `MediaLibrary` のポートが加わり、`HostSession::Ports` が増える。JUCE を使わない `pa-engine` のビルドは、録音も再生もできない実装を渡す（ファイルを開くと `IO_ERROR`）。
- `control-protocol` の entity、コマンド、イベントが増えるので、`ui/src/ipc/` も同じ PR で変える（AGENTS.md 4.4）。
- 実装は 2 本の PR に分ける。
  1. この ADR と `media`（JUCE の WAV、FLAC の読み書き）、`AudioFileFormat`、`length_frames()`。
  2. `session`、`control-protocol`、`persistence`、`pa-engine`（ディスク I/O スレッド、録音と再生の組み立て）、`remote-pa`（メディアの窓）、`ui/`（メディア画面）。
- 実機での確認（録音中にディスクへ負荷をかける、容量の小さいドライブに録る、異常終了の後にファイルを開く）は、`docs/testing/recording-and-playback.md` の手順で行う。
