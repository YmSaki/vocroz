# 0031. 録音タップと再生ノードの形と、ディスクの不調の扱い

- 状態: 採用（2026-11-09）

## コンテキスト

Beta2 では、任意のチャンネルやバスをマルチトラックで録音し（WAV / FLAC）、音声ファイルを任意のバスへ再生できるようにする（B2a、Issue #28）。
仕様書の Beta2 の合格条件は「録音中のディスク負荷や容量不足でライブ音声を止めないこと」。
置き場所は ADR-0009 で決めた（録音タップ、再生ノード、ディスク I/O スレッド側の排出と先読みは `audio-core`、ファイル形式は `media`、トラックと録音の状態と失敗の扱いは `session`）。
この ADR では、ADR-0018 のルーティンググラフに録音と再生をどう組み込むか、オーディオスレッドとディスク I/O スレッドの受け渡し、ディスクが遅いときと容量が足りないときの振る舞いを決める。

前提は次のとおり。

- オーディオスレッドは第 9 節のリアルタイム制約に従う。ファイル I/O、ロック、ヒープの確保をしない。
- マルチトラック録音は、あとで DAW に並べて編集する用途が中心で、トラック同士の時間軸がそろっていることが重要。
- 再生は合奏中の BGM や効果音の用途で、操作で音がぶつ切りにならないこと（クリックノイズを出さないこと）が要る。

## 決定

### ポート

- `audio-core` にポート `AudioFileWriter`（`write()`、`finish()`）と `AudioFileReader`（`channel_count()`、`read()`、`seek()`）を定義する。どちらもディスク I/O スレッドから呼び、ブロッキング I/O を含んでよい。ファイルを開く処理（パス、形式、ビット深度）は `media` のファクトリー関数が持つ。
- 失敗の理由は `AudioFileError`（`kDiskFull`、`kIoError`、`kNotFound`、`kUnsupportedFormat`）。容量不足を他の失敗と分けるのは、`session` が「空き容量が足りない」と表示して保存先の変更を促せるようにするため。
- エンジン内は 48kHz だけを扱う。ファイルのサンプルレートが違えば `AudioFileReader` の実装（`media`）が変換する。デバイス境界で `device` が変換するのと同じ考え方。

### 受け渡し

- 録音と再生のどちらも、トラックごとに SPSC のロックフリーのリングバッファ（`SampleRingBuffer`）を 1 本持つ。録音はオーディオスレッドが書いてディスク I/O スレッドが読み、再生はその逆。
- 長さは録音 4 秒、再生 2 秒を既定にする（`kDefaultRecordingBufferFrames`、`kDefaultPlaybackBufferFrames`）。HDD のスピンアップやウイルス対策ソフトの走査で数秒止まるのを吸収する長さで、32 トラックでも数十 MB に収まる。再生は読み直せるので短くする。
- ディスク I/O スレッドの周期処理は `RecordingTrack::drain()` と `PlaybackTrack::fill()` を呼ぶだけにする。スレッドそのものを起こして回すのは、トラックの一覧を持つ `session` とコンポジションルートの役割とする。

### 録音タップ

- ノードの種類 `NodeKind::kRecordTap` を加える。入力の加算を `RecordingTrack` に書き、出力を持たない（送り元にすると `kInvalidConnection`）。チャンネル数（1 か 2）はトラックで決まり、ステレオからモノラルへの結線は既存の規則どおり受け付けない（`kChannelMismatch`）。
- フェーダーの前を録るときは `SendTap::kPreFader` でつなぐ。録音タップへのプリフェーダーの結線には、センドレベルを付けなくてよい。センドレベルの必須化は新規参加時に聞こえる音を初期ミュートにするためのもので、録音タップは聞こえる音を作らず、フェーダーの位置に関わらず入力を録ることが目的だから。
- 録音の開始と停止は、タップを含むグラフの適用で表す。録音中のフラグは持たない。複数のトラックのタップを 1 つのグラフで足し外しすれば、グラフのスワップは 1 ブロックの境目で起きるので、すべてのトラックが同じサンプルから始まり、同じサンプルで終わる。トラックごとのフラグを順に立てる方式では、立てる間にブロックの境目をまたぐとトラック間でずれる。
- 停止は、タップを外したグラフを適用し、古いグラフの破棄（`Mixer::is_graph_settled()`）を待ってから `RecordingTrack::finish()` を呼ぶ。`finish()` は残りを書き出してから `AudioFileWriter::finish()` でファイルを閉じる。

### ディスクの不調

- 書き込みが遅れてリングバッファに 1 ブロックぶんの空きがなければ、オーディオスレッドはそのブロックを書かずに捨て、捨てたフレーム数を数える（`dropped_frames()`）。待たないのでライブ音声は止まらない。ブロックの一部だけを書くことはしない。
- 捨てた区間は、ディスク I/O スレッドが同じ長さの無音で埋める。欠落の位置（リングバッファの通算位置）と長さは、固定長の SPSC キューでディスク I/O スレッドへ渡す。欠落の後のサンプルは、欠落の記録をキューに入れられてから書く。こうすると、欠落があってもファイルの長さと時間軸は他のトラックとそろったままになる。欠落を詰めて書く方式では、それ以降のトラックの時間軸がずれ、編集で合わせ直せなくなる。
- 書き出しが失敗したら（容量不足を含む）、そのトラックの書き出しを止め、以降は届いたサンプルを捨てて同じエラーを返し続ける。容量不足のディスクに書き続けても成功しないうえ、他のトラックの書き込みを遅らせるため。止めた時点で書けたぶんは、`finish()` でファイルを閉じて再生できる形で残す。
- 欠落があったトラックと書き出しの失敗を UI にどう示すか、ほかのトラックも止めるかは `session` が決める（続きの PR）。

### 再生ノード

- ノードの種類 `NodeKind::kPlayer` を加える。入力を持たず（結線を受けると `kInvalidConnection`）、出力のチャンネル数はトラックで決まる。モノラルのファイルはストリップにもバスにもつなげ、ステレオのファイルはバスへつなぐ。
- 再生ノードはフェーダーを持たない。音量は後段のストリップかバスのフェーダーで決める。構築直後は停止中で、`play()` を呼ぶまで鳴らない（初期ミュート）。
- 開始、一時停止、シークは 10ms のフェード（`GainRamp`）で切り替える。シークでは、ディスク I/O スレッドが新しい位置から読み直し、「新しい区間がリングバッファのどこから始まるか」を固定長の SPSC キューでオーディオスレッドへ渡す。オーディオスレッドは、再生中ならフェードアウトし終えてから古い先読みを読み飛ばし、フェードインする。リングバッファの読み込み位置を動かすのは消費者であるオーディオスレッドだけにし、SPSC の前提を崩さない。
- 先読みが間に合わなければ、待たずに無音で埋め、埋めたフレーム数を数える（`underrun_frames()`）。ファイルの終わりの後の無音は数えない。ファイルの終わりに達しても、オーディオスレッドは再生の指示を書き換えない（`at_end()` を見た `session` が停止にする）。指示を書くスレッドをコントロールスレッドだけにして、操作との競合を避けるため。
- 再生ノードは停止中もグラフに置いたままにする。シークの反映は再生ノードの処理の中で行うため。

## 理由

- 録音と再生を `AudioSource` や `PluginProcessor` のポートの実装として外に置かず、ノードの種類として `audio-core` に持つのは、オーディオスレッド側の処理（リングバッファ、欠落の記録、フェード）がファイル形式に依存しないドメインの規則で、Linux の CI で RealtimeSanitizer の検査と単体テストをしたいため。ファイル形式だけが JUCE に依存するので、ポートの向こうの `media` に置く。
- 録音の開始と停止をグラフの適用で表せば、トラック間の同期を新しい仕組みなしに保証できる。グラフのスワップはすでに 1 ブロックの境目で起きることが保証されている（ADR-0018）。
- 欠落を無音で埋めると、欠落した区間は無音として聞こえるが、トラック間の時間軸は崩れない。欠落の量は数えて `session` に渡せるので、録音の品質が落ちたことは利用者に示せる。

## 結果

- `audio-core` に `AudioFileWriter`、`AudioFileReader`、`AudioFileError`、`RecordingTrack`、`PlaybackTrack`、`NodeSpec::make_record_tap()`、`NodeSpec::make_player()`、`GraphError::kMissingTrack` が加わる。テストダブルは `FakeAudioFileWriter`（書き込みの遅延と容量不足の模擬）と `FakeAudioFileReader`。
- 録音タップへのプリフェーダーの結線だけは、センドレベルなしで適用できる。
- 録音タップは、同じグラフの中で遅延の違う位置（プラグインの前と後など）をつなぐと、トラック間でその遅延の差だけずれる。PDC は聞こえる経路の合流をそろえる規則で、録音タップどうしはそろえない。必要になったら、録音タップを PDC の合流点として扱う規則を足す。
- 続きの作業: `media` の WAV / FLAC の実装（JUCE 内蔵の FLAC、ADR-0009）、`session` のトラックの一覧と録音の開始と停止、ディスク I/O スレッドの周期処理、欠落と失敗の通知、`control-protocol` のコマンドとイベント、メディア・録音管理の画面（`ui/src/screens/media/`）。
- 受け入れテスト（ADR-0009）の「録音中に書き込みを遅らせても音声が途切れないこと」は、単体テストでは `FakeAudioFileWriter` の遅延と容量不足で確かめ、実機では `docs/testing/` の手順で確かめる。
