# 0007. 起動インターフェース（コマンドライン引数、単一インスタンス、終了コード）

- 状態: 採用（2026-11-07）

## コンテキスト

`remote-pa` は親機モードと子機モードを起動ごとに選ぶ（`docs/adr/0005-ui-juce-webview.md`）。
起動の経路は、スタートメニューのショートカット、招待 URL（`docs/adr/0006-invite-url-scheme.md`）、コマンドライン（検証、サポート、自動テスト）の 3 つがある。
どの経路でも同じ規則でモードと引数を解釈しないと、経路ごとに振る舞いが変わる。
同じ PC で親機と子機を同時に動かす検証や、受け入れテストの自動化にも、引数でデータの置き場所やモードを指定できる必要がある。

## 決定

### `remote-pa` の引数

| 引数 | 意味 |
| --- | --- |
| （なし） | 親機モード |
| `--mode=host` / `--mode=client` | モードを明示する。`--client` は `--mode=client` の別名として残す |
| `--join=<招待 URL または招待コード>` | 子機モードで起動し、その招待の確認画面を開く。`--mode` を省略すると子機モードになる |
| `vocroz://join?code=<招待コード>`（位置引数） | URL スキームからの起動。`--join` と同じ扱い |
| `--data-dir=<パス>` | 設定、ログ、キャッシュの置き場所を変える（既定は `%LOCALAPPDATA%\VOCROZ\`）。単一インスタンスの範囲もこのパスごとに分かれる |
| `--lang=ja` / `--lang=en` | 表示言語を上書きする（既定は OS の表示言語） |
| `--log-level=error\|warn\|info\|debug` | ログの詳細度（既定は `info`）。ログに秘密情報を出さない規則は詳細度によらない |
| `--no-update-check` | 起動時の更新確認をしない（オフラインの会場や検証用） |
| `--rendezvous-url=<URL>` | ランデブーサーバーのベース URL を変える（検証用。既定はビルド時の値。`docs/adr/0030-remote-pa-assembly.md`） |
| `--version` | バージョンを表示して終了する |
| `--help` | 引数の一覧を表示して終了する |

- 矛盾する引数（`--mode=host` と `--join` の同時指定など）や未知の引数は、エラーとして表示し、終了コード 2 で終了する。黙って無視も推測もしない。
- インストーラーは「VOCROZ（親機）」と「VOCROZ（子機）」の 2 つのショートカットを作り、それぞれ引数なしと `--mode=client` で起動する。

### `pa-engine` と `pa-updater` の引数

- `pa-engine` は `remote-pa`（親機モード）が起動する内部プロセスで、`--data-dir`、`--log-level`、`--version` だけを受け付ける。名前付きパイプの名前は `--data-dir` から導出するので、引数では受け取らない。
- `pa-updater` の引数は内部用とし、P5 で決める。利用者向けには公開しない。

### 単一インスタンス

- 単一インスタンスの範囲は「ユーザー × `--data-dir` × モード」とする。名前付きミューテックスの名前はこの 3 つから導出する。
- 同じ範囲のインスタンスがすでに動いていれば、新しいプロセスは引数（`--join` など）を名前付きパイプで既存のインスタンスに渡し、既存のウィンドウを前面に出して終了する。
- 親機モードと子機モードは範囲が別なので、同じ PC で同時に起動できる（合奏の検証や、親機の操作者が自分も演奏する場合のため）。

### 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 正常終了 |
| 1 | 起動後の致命的なエラー（ログに原因を書く） |
| 2 | 引数の誤り |
| 3 | 既存のインスタンスに引数を渡して終了した |

## 理由

- 起動経路が 3 つあっても、すべてを 1 つの引数の規則に落とせば、モードの決まり方が経路によって変わらない。URL スキームもショートカットも、この引数の組み合わせの 1 つにすぎない。
- `--data-dir` があれば、1 台の PC で親機と複数の子機を別々の設定で起動でき、受け入れテストを自動化しやすい。インストール先も環境変数も変えずに済むので、環境を汚さない。
- 誤った引数を黙って無視すると、ショートカットや手順書の誤りに気付けず、本番で意図しないモードが起動する。

## 結果

- 引数の定義とパースは `apps/pa-desktop/src/launch_options.{h,cpp}` の純粋関数に置き、単体テストを付ける。エントリポイントはパースの結果をコンポジションルートに渡すだけにする。汎用の引数処理は `modules/common` の `cli` を使う。
- 単一インスタンス化と引数の受け渡しは `apps/pa-desktop/src/win/` のアダプターで行う。
- 現在の `--client` と `--version` の振る舞いは変えない。
