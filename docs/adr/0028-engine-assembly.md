# 0028. pa-engine の組み立て、単一起動、自動終了、仮の部品

- 状態: 採用（2026-11-09）

## コンテキスト

`pa-engine` は、audio-core、transport、session、device、network、ipc、persistence を 1 つのプロセスに組み立てる親機のオーディオエンジンである。
ADR-0007 は、`pa-engine` が `--data-dir`、`--log-level`、`--version` だけを受け付けること、終了コード（0 正常、1 致命的なエラー、2 引数の誤り、3 すでに起動している）、単一インスタンスの範囲を「ユーザー × `--data-dir` × モード」にすることを決めている。
ADR-0008 は、本番中だけスリープを抑止すること、クラッシュダンプを `<data-dir>\crash` に残すこと、UI が落ちてもエンジンは動き続け、つなぎ直した UI にスナップショットを送ることを決めている。
ADR-0020 の名前付きパイプのサーバーは、UI の接続をまたいで 1 つのチャンネルとして振る舞い、UI の切断を知らせない。UI がつながっていない間の `send()` は `kClosed` で失敗する。

組み立てで決めることは、スレッドへの割り当て、2 つ目の起動の検出、エンジンが自分で終わる条件、ミキサーのグラフの形、出力デバイスの開き方、まだ実装のないポート（設定の永続化、ランデブーサーバーとの通信、子機との通信）の扱いである。

## 決定

### 構成とスレッド

- OS に依存しない部品は静的ライブラリ `pa_engine_core`（`apps/pa-engine/src/`）に置き、Linux の CI で単体テストする。Win32 を呼ぶ部品は `apps/pa-engine/src/win/` に置き、`composition_root` は Windows でだけビルドする。
- **コントロールスレッド**（メインスレッド）: `ControlLoop` が 50ms ごとに周期処理を回し、ほかのスレッドから積まれた処理を実行する。`HostSession`、ミキサーの操作、UI への送信はこのスレッドだけで行う。`HostSession::tick()` は 100ms ごとに呼ぶ。
- **パイプの受信スレッド**: UI のメッセージを `control-protocol` でデコードし、検証済みのメッセージをコントロールスレッドのループに積む。デコードの失敗は、項目の名前だけをログに残す（メッセージの本文は残さない）。
- **オーディオスレッド**: device の出力のスレッドが `Mixer::render()` だけを呼ぶ。パラメーターは Mixer の SPSC キュー、構造の変更はグラフのスワップで渡す（AGENTS.md 6.1）。
- **出力デバイスの抜去**: device のスレッドが `Mixer::engage_safety_mute()` を直接呼んでから、残りの処理（出力の停止、`HostSession::on_output_device_lost()`）をコントロールスレッドに積む。コントロールスレッドを待たずに音を止めるためである。

### 単一起動

- 名前付きミューテックス `Local\<パイプの名前の最後の要素>` を起動時に作る。パイプの名前は ipc がユーザーの SID と `--data-dir` から導出する（ADR-0020）ので、範囲は「ユーザー × `--data-dir`」になる。`pa-engine` は親機モードだけなので、モードは名前に含めない。
- すでにある場合は、UI のパイプも開かずに終了コード 3 で終わる。`remote-pa` は 3 を「すでに動いているエンジンにつなぐ」合図として扱う。

### 自動終了

- **セッションがなく、UI もつながっていない状態が 30 秒続いたら、正常終了する。** セッションがある間は、UI がなくても終わらない（UI の障害で音を止めないため）。
- UI がつながっているかは、パイプへの送信の成否で判断する。メーターを毎周期（20Hz）送るので、UI が切断すると 50ms 以内に送信が失敗し、UI からメッセージが届くか送信が成功すれば、つながっているとみなす。
- 30 秒は、`remote-pa` の再起動とつなぎ直しには十分で、`remote-pa` が落ちたあとに `pa-engine` だけが残り続けない長さとして決めた。

### スリープの抑止とセッションのロック

- セッションの状態が ACTIVE の間だけ `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` でスリープを抑止する（ADR-0008）。
- セッションがある間（IDLE 以外）は、`update::session_lock_name()` の名前付きミューテックスを持つ。`pa-updater` はこれを見て、本番中の更新を止める（ADR-0013）。

### クラッシュダンプ

- 起動時に `<data-dir>\crash` を作り、`SetUnhandledExceptionFilter` で `MiniDumpWriteDump`（`MiniDumpWithDataSegs`）を書くハンドラーを入れる。ファイル名は `pa-engine-YYYYMMDD-HHMMSS-<pid>.dmp`。
- 起動時に古いダンプを消し、新しい順に 4 つだけ残す。次のクラッシュで書くものと合わせて最大 5 つになる。ダンプのパスはハンドラーの中でヒープを使わずに組み立てる。

### ミキサーのグラフ

- `EngineMixer`（session の `MixerControl` の実装）が、ストリップ、Master、バス、センドにフェーダーとメーターを割り当て、変更のたびに `build_mixer_graph()` でグラフを組み立てて `Mixer::apply_graph()` で差し替える。Mixer の容量はフェーダー、メーターとも 256。
- グラフは「ソース → ストリップ（手動ディレイ、プリフェーダーのメーター、フェーダー）→ Master → 安全リミッター → メインの出力（チャンネル 0 と 1）」を暗黙の経路として必ず持つ。ルーティングの構成のバス、遅延ノード、追加の出力、センドを、その上に加える（ADR-0018、ADR-0026）。
- **追加の出力にも安全リミッターを通す。** キューの返しも出演者の耳に届く出力なので、メインの出力と同じく過大な音を出さない。
- 新しいストリップ、バス、センドは、グラフに入れる前にフェーダーをミュートで 0 dB に戻す（初期ミュート）。返したフェーダーも戻してから空きに戻す。同じ entity_id のバスとセンドは、構成を適用し直してもフェーダーを引き継ぐ。
- 送り元か送り先が見つからないセンドはグラフから外し、そのフェーダーをミュートして警告を残す。`remove_channel()` は今の構成のままグラフを組み直すので、削除したストリップを送り元にするセンドはこの時点でミュートされる。session が参照を外した構成の適用し直しに失敗しても、センドから音は出ない（ADR-0026 のフェイルセーフ）。
- フェーダーの操作が Mixer のキューの満杯で失敗したら、順序を保って次の周期に送り直す。Master のミュートが失敗したときは、送り直しを待たずに安全ミュートで止める。Master のミュートを解く操作は、出力デバイスの抜去でかけた安全ミュートも一緒に解く（解除はオペレーターの操作だけで起きる）。

### 出力デバイス

- 起動時に、保存された出力デバイスの ID があればそのデバイスだけを開く。開けなければ何も開かず、既定のデバイスへフォールバックしない（ADR-0023）。

**追記（2026-11-09、出力デバイスの選択）**: UI から出力デバイスを選べるようにした。

- control-protocol に離散コマンド `select_output`（対象は `session`。`device_id` が null なら出力なし）、エラーコード `DEVICE_UNAVAILABLE`、`SessionInfo` の `output_device_id` と `output_devices`（選べるデバイスの一覧）を足した。
- 出力デバイスを開く判断は session に移した。session に `OutputDeviceControl` ポート（一覧、開く、閉じる）を足し、`HostSession` が起動時に保存した ID のデバイスを開き、`SelectOutput` で開き直す。エンジンは `EngineOutputDevices` で、device の `AudioDeviceCatalog` と `make_wasapi_audio_output()` を使って実装する。`HostSession::on_output_device_opened()` と `on_output_device_closed()` は外した。
- 開き直すときは、前の出力を止めてから次を開く。ミキサーを 2 つのオーディオスレッドから呼ばないためである。開けなければ DEVICE_UNAVAILABLE で拒否し、未選択（NONE）のままにする。前のデバイスにもほかのデバイスにも戻さない。
- 選んでも Master のミュートは変えない。抜去で LOST になったあとに選び直しても、SAFETY のミュートはオペレーターが解くまで続く。
- LOST のときは抜けたデバイスの ID を残す。挿し直したデバイスを選び直しやすくするためである。
- デバイスの一覧は、UI の接続（`hello`）、選択、抜去のときに列挙し直す。スナップショットはコントロールスレッドが周期的に作るので、そのたびには列挙しない。
- 選択は設定に保存する。起動時に開けなかったときは保存した ID を消さず、次の起動でまた試す。
- 抜去の通知が積まれたあとにオペレーターが別のデバイスを選んでいた場合も、通知を受けた時点で開いているデバイスを閉じて LOST にする。ミキサーにはすでに安全ミュートがかかっているので、session の表示をそれに合わせ、オペレーターに選び直してもらう（フェイルセーフ）。

### 仮の部品

まだ実装のないポートは、次の仮の部品で埋める。どれも `composition_root` のメンバーを差し替えるだけで本物に替えられるようにし、ドメインには手を入れない。

| ポート | 仮の部品 | 振る舞い | 置き換え |
| --- | --- | --- | --- |
| `common::Logger` | `StderrLogger` | 標準エラー出力に書く | persistence のログファイル（P1、#20） |
| `session::SettingsStore` | `MemorySettingsStore` | 起動のたびに空。読み込みは `kNotFound` | persistence の設定ファイル（P1、#20） |
| `session::RendezvousClient` | `OfflineRendezvousClient` | 招待の登録はループ経由で `kUnreachable` を返す | network の HTTPS クライアント（N1 の続き、#18） |
| `session::PeerLink` | `UnconnectedPeerLink` | 子機に何も送らない | network と transport による子機の受信（E1 の 2 本目） |

- 親機の長期鍵（`StaticKeyPair`）は、設定の永続化ができるまで起動のたびに作る。
- 招待 URL の基底（`/join` を持つランデブーサーバーの URL）は、CMake のキャッシュ変数 `VOCROZ_RENDEZVOUS_URL` から生成するヘッダーで渡す。

**追記（2026-11-09、P1 #55 と招待の HTTPS #56 のマージ後）**: 次のとおり本物に差し替えた。

- ログは persistence の `make_rotating_file_logger()`（`<data-dir>\logs\pa-engine.log`）。データフォルダを決められないときだけ、起動できない理由を `StderrLogger` で標準エラー出力に書く。
- 設定は `make_json_settings_store()`。`MemorySettingsStore` は消した。
- 親機の長期鍵は `make_dpapi_secret_store()` に保存し、起動のたびに読み込む（`load_host_keys()`）。ない、壊れている、長さが不正なら作り直して保存する。読み込みが I/O の失敗なら、保存した鍵を上書きしないよう、その起動だけの鍵を使う。秘密鍵から鍵ペアを作り直すため、transport に `StaticKeyPair::from_private_key()` を足した。
- ランデブーサーバーとの通信は network の `HttpsRendezvousClient`。結果は作業用のスレッドから届くので、`InviteResultRelay` がコントロールスレッドのループに積んで session に渡す。`VOCROZ_RENDEZVOUS_URL` が空か、HTTPS の通信を始められないときは、`OfflineRendezvousClient`（セッションを作れない。オフラインの会場と同じ振る舞い）を使う。
- `pa-engine.exe` に `pa-updater` と同じアプリケーションマニフェスト（`activeCodePage` を UTF-8）を入れた。`remote-pa` が渡す `--data-dir` は `%LOCALAPPDATA%` の下なので、ユーザー名に日本語を含むと argv が化けるため。

## 理由

- **UI の接続を送信の成否で推定する理由**: ADR-0020 のパイプのサーバーは、UI の切断を通知しない。通知を足すには ipc の契約を変える必要があるが、エンジンはメーターを 20Hz で送り続けるので、送信の失敗で十分早く（50ms 以内）切断を知ることができる。
- **単一起動にミューテックスを使う理由**: パイプの作成の失敗でも 2 つ目を検出できるが、パイプは UI の接続のたびにインスタンスを作り直すため、失敗の理由が「すでに動いている」なのか一時的な競合なのかを区別しにくい。ミューテックスはプロセスが落ちれば OS が解放するので、クラッシュ後の再起動も妨げない。
- **ダンプを起動時に整理する理由**: クラッシュハンドラーの中ではヒープの確保とディレクトリの列挙を避けたいので、残す数の調整は次の起動で行う。
- **センドのフェーダーを外したときにミュートする理由**: グラフから外したセンドのフェーダーが解除されたまま残ると、次に同じ識別子が割り当てられたときに音が出る。フェイルセーフ（AGENTS.md 1.2）に従ってミュートする側に倒す。
- **仮の部品を使う理由**: 設定の永続化（P1）とランデブーサーバーとの HTTPS 通信は別のスレッドで並行して作られている。それらを待たずに、UI とセッション、ミキサー、出力デバイスの組み立てを先にマージすれば、`remote-pa` とルーティング画面の結合を先に始められる。

## 結果

- `pa-engine` は起動して UI とつながり、スナップショットとイベントを送り、ルーティングの構成をミキサーに適用できる。UI が落ちても動き続け、つなぎ直した UI にスナップショットを送る（`pa_engine_smoke_tests`、Windows）。
- 出力デバイスを選ぶ UI のコマンドがまだなく、設定も保存されないので、この段階では出力デバイスを開かない（出力デバイスの選択は追記のとおり追加した）。出力デバイスの選択（control-protocol、session、UI）と、子機の受信（network、transport → `EngineMixer::attach_source()`）は、続きの PR で追加する。
- `known_paths`（`%LOCALAPPDATA%\VOCROZ`）は `apps/updater` と同じ知識を持つ。次の定期リファクタリングで `update` か `common` への移動を検討する（drift）。
- `common` に `SteadyClock`（`Clock` の `std::chrono::steady_clock` による実装）を追加した。ステートレスで OS の API を呼ばないため、共通基盤に置く。
