# 0005. UI は JUCE の WebBrowserComponent でホストし、親機と子機で 1 つのアプリを使う

- 状態: 採用（2026-11-07）

## コンテキスト

JUCE は VST3 のホスティング、オーディオ系のライブラリ、GUI をまとめて提供するため採用している。
画面は TypeScript のフロントエンドで作る前提で、WebView のホストを JUCE と別に用意すると、ネイティブの GUI 基盤が 2 つになる。
また、親機モードと子機モードは同じ実行ファイル（`remote-pa`）で動くので、WebView のホストを両モードで共有する置き場所が必要になる。
名前付きパイプのアダプターの置き場所も決まっていなかった。

## 決定

- WebView は JUCE の `WebBrowserComponent`（Windows のバックエンドは WebView2）でホストする。
- フロントエンドは `ui/` に 1 つだけ置き、親機と子機の両方の画面を持つ。ビルド成果物（`ui/dist`）は `remote-pa` にバイナリリソースとして埋め込み、JUCE のリソースプロバイダーで配信する。
- WebView のホストとネイティブ関数のブリッジは、新設するアダプターモジュール `modules/webui` に置く。ホストは JSON を中継するだけで、検証とコマンドの適用は行わない。
- 名前付きパイプのクライアントとサーバーは、新設するアダプターモジュール `modules/ipc` に置く。
- JUCE による実装は `src/juce/` に置く。JUCE は OS 非依存なので、Win32 を直接呼ぶ実装の `src/win/` とは分ける。
- 動作モードは起動ごとに固定する。招待 URL や `--client` で起動したら子機モード、それ以外は親機モード。起動中に切り替えない。
- ウィンドウのサイズと最小サイズは、モードごとにコンポジションルートで決めて `webui` に渡す。子機モードは親機モードより小さくする。

## 理由

- GUI 基盤を JUCE に一本化でき、VST3 のプラグインエディターと同じウィンドウ基盤で扱える。
- `client-desktop` は `pa-desktop` に依存できないため、両モードが共有するホストはモジュールに置く必要がある。
- ホストを中継だけにすれば、正となる状態をエンジンだけが持つ前提（エンジン主権）を崩さない。
- 親機モードは `pa-engine` に接続し、子機モードは自らキャプチャと送信を行うので、プロセス内の構成がまったく違う。起動中にモードを切り替えると、片方の後始末が漏れて音声が出続けるなどの事故につながる。

## 結果

- `modules/README.md` と AGENTS.md の 2.1、3.3、4.2、5.1、5.3 を更新する。
- 子機モードの UI ブリッジはプロセス内の子機ロジックにつながり、親機モードの UI ブリッジは名前付きパイプ経由で `pa-engine` につながる。どちらも `control-protocol` のメッセージを使う。
- `ui/src/main.ts` は、起動時にネイティブ側から受け取ったモードで表示する画面（`screens/mixer` か `screens/client`）を選ぶ。
