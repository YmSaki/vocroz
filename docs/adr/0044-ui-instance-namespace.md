# 0044. UI のインスタンスごとに request_id と seq の名前空間を分ける

- 状態: 採用（2026-11-15）

## コンテキスト

`pa-engine` は、親機の画面を閉じても動き続ける（ADR-0020、AGENTS.md 2.2）。
エンジンの `HostCommandHandler` は、離散コマンドの `request_id` の重複を覚えておき、`set_gain` の `seq` の最大値を entity ごとに覚えておく。
どちらも、UI の再表示にまたがって覚え続ける。

一方、UI の `EngineClient` は、作られるたびに `request_id` の番号と entity ごとの `seq` を 1 から数え直す。
接頭辞（ミキサーの窓は `m`、ルーティングの窓は `rt`、ADR-0038）は窓の種類ごとに決まっており、開き直しても変わらない。
そのため、次の操作のあとで、新しい画面の操作が前の画面の重複や古い値とみなされて捨てられていた（Issue #98）。

- 親機の画面を閉じて開き直す。
- ルーティングの窓だけを閉じて開き直す。
- エンジンにつなぎ直して、`WebUiHost::reload()` で画面を読み込み直す。

捨てられた離散コマンドには ACK も拒否も返らない。
Master のミュートを押しても音が止まらないので、フェイルセーフ（AGENTS.md 1.2）に反する。

`hello` を受けたときにエンジンが覚えている値を消す方法は採らない。
ミキサーの窓とルーティングの窓は 1 本の接続を共有するので（ADR-0038）、片方の窓の `hello` で、もう片方の窓の重複の判定と順序まで消してしまう。

## 決定

- UI のクライアント（`EngineClient`）は、作られるたびに送り元の ID（`origin`）を振る。
  - 形は `<接頭辞>-<16 進 16 文字の乱数>`（例: `m-3f9a0c1d5e7b2a46`）。接頭辞はこれまでどおりコンポジションルートが渡す。
  - 乱数は `crypto.getRandomValues()` で 8 バイト作る。時刻から作ると、時計が巻き戻ったときに前の画面の ID と重なりうるため。
- 離散コマンドの `request_id` は `<origin>.<番号>` にする。メッセージの形は変えない。
  - エンジンの重複の判定はこれまでどおり文字列で行う。前の画面の `request_id` とは重ならないので、開き直した画面の最初のコマンドから適用される。同じ画面の中の重複は、これまでどおり捨てる。
- `set_gain` に `origin` を加える。必須のフィールドで、規則は `request_id` と同じ（英数字と `_ - . :`、64 バイトまで）。
  - エンジンは entity ごとに、最後に適用した `origin` と `seq` を覚える（`session` の `GainSequenceGate`）。同じ `origin` から届いた小さい `seq` だけを古い値として捨て、別の `origin` からの値は届いた順の後勝ちで受け付ける。
  - 子機（`ClientSession`）の送信レベルも同じ規則にする。子機の画面の読み込み直しでも同じことが起きるため。
- `gain_ack` にも、適用した `set_gain` の `origin` を入れて返す。
  - `gain_ack` は接続を共有するすべての窓に届く（ADR-0038）。`EngineClient` は自分の `origin` でない `gain_ack` を無視する。`seq` の意味（その値以下はすべて適用済み）は、送り元ごとにしか成り立たないため。

## 理由

- 送り元を区別するのは UI の生存期間と同じ単位であり、エンジンは UI がいつ作り直されたかを知らなくてよい。`hello` の扱いも、ルーティングの窓の開閉も変えずに済む。
- `request_id` は UI が自由に振る文字列なので、離散コマンドはメッセージの形を変えずに直せる。
- `set_gain` には送り元を表すものがないので、フィールドを加えるしかない。`seq` の開始値を時刻などで大きくする方法は、時計の巻き戻りでフェーダーが効かなくなるので採らない。
- UI とエンジンは同じインストーラーで配るので（ADR-0015）、`origin` を必須にしても古い UI との互換は問題にならない。

## 結果

- `control-protocol` の `SetGain` と `GainAck` に `origin` が増える。`ui/src/ipc/messages.ts` と `modules/control-protocol/tests/data/` の例も同じ PR で変える（AGENTS.md 4.4）。
- `session` に `GainSequenceGate` が増え、Master、チャンネルストリップ、バスとセンド、子機の送信レベルの順序の判定がこの 1 か所にまとまる。
- `request_id` は 30 文字前後になる。上限の 64 バイトには収まる。
- 窓が同じ entity を同時に操作した場合は、届いた順の後勝ちになる。今はミキサーの窓とルーティングの窓が操作する entity は重ならない（ADR-0038）。
