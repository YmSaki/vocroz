# 0020. 名前付きパイプのフレーミングとアクセス制御、WebView のブリッジ、WebView2 SDK の取得

- 状態: 採用（2026-11-08）

## コンテキスト

`docs/adr/0003-ipc-named-pipe-json.md` で、親機の `remote-pa` と `pa-engine` は、ログイン中ユーザーの SID だけに許可した名前付きパイプで、長さ付きの JSON をやり取りすると決めた。
`docs/adr/0005-ui-juce-webview.md` で、UI は JUCE の `WebBrowserComponent`（WebView2）でホストし、`ui/dist` をリソースプロバイダーで配信すると決めた。
`docs/adr/0015-control-protocol-messages.md` で、両者が実装する `MessageChannel` ポートを定義した。

一方で、次の点は決まっていなかった。

- 長さの前置きの形と、不正なフレームを受け取ったときの扱い。
- パイプの名前、ACL の具体的な形、なりすまし（パイプの名前の先取り）への対策。
- 切断と再接続の扱い。UI が再起動したとき、`pa-engine` が再起動したときにどうつながり直すか。
- UI が応答しなくなったとき、エンジンの送信がどうなるか。
- WebView2 の SDK（`WebView2.h` と `WebView2LoaderStatic.lib`）をどう取得するか。JUCE は NuGet のパッケージを手元に入れる前提で、CMake からは取得しない。
- ネイティブ側と UI の間のイベントの名前、ページの読み込み前に届いたメッセージの扱い、スレッド。

## 決定

### フレーミング

- 1 フレームは、本文のバイト数を表す 4 バイトの符号なし整数（リトルエンディアン）と、本文（UTF-8 の JSON 1 メッセージ）からなる。
- 本文の長さが `control_protocol::kMaxMessageBytes`（64 KiB）を超えるフレームは不正とし、本文を読まずに接続を切る。長さ 0 のフレームはフレーミングでは拒否せず、JSON のデコード（`control-protocol`）で不正として扱う。相手は再接続して `hello` からやり直す。不正な長さのあとは境界を信用できず、読み飛ばして続けると後続のメッセージを取り違えるため。
- フレームの組み立てと分解は OS に依存しない純粋なコード（`modules/ipc/src/detail/`）に置き、Linux の CI でも単体テストする。

### パイプの名前とアクセス制御

- 名前は `\\.\pipe\vocroz-engine-<ユーザーの SID>-<データフォルダのハッシュ>` とする。ハッシュは `--data-dir` の絶対パスを小文字にした UTF-8 の FNV-1a（64 ビット、16 桁の 16 進数）。`docs/adr/0007-launch-interface.md` のとおり、名前は `--data-dir` から導出し、引数では渡さない。SID を入れるのは、ほかのユーザーのエンジンと名前が衝突しないようにするため。
- サーバー（`pa-engine`）は次の設定でパイプを作る。
  - セキュリティ記述子は `O:<SID>D:P(A;;GA;;;<SID>)`。所有者と、ただ 1 つの ACE をログイン中ユーザーの SID にし、継承を受けない（`P`）。管理者として起動した場合も、所有者が Administrators にならないよう明示する。
  - `FILE_FLAG_FIRST_PIPE_INSTANCE`。同じ名前のパイプがすでにあれば作成に失敗する。ほかのプロセスが先に同じ名前で待ち受けていたら起動を止める。
  - `PIPE_REJECT_REMOTE_CLIENTS`。ネットワーク越しの接続を拒否する。
  - インスタンスは 1 つ。同時につながる UI は 1 つだけで、2 つ目の接続はビジーになる。
- クライアント（`remote-pa`）は `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` で開き、サーバーに識別以上の偽装（impersonation）を許さない。開いたあと、パイプの所有者の SID が自分の SID と一致することを確かめ、一致しなければ切断する。エンジンが起動していない間に、ほかのユーザーが同じ名前で待ち受けていた場合に、コマンドを渡さないため。
- パイプはバイトモードで使う。メッセージの境界は長さの前置きで表すので、メッセージモードは使わない。

### 切断と再接続

- サーバーの `MessageChannel` は、UI がつながり直しても同じオブジェクトのままとする。UI が切断したら次の接続を待ち、つながった UI が `hello` を送ってスナップショットを受け取り直す。UI の切断は `on_closed()` で知らせない（エンジンは UI の有無にかかわらず動き続けるため）。`on_closed()` は、OS のエラーで待ち受けを続けられなくなったときだけ呼ぶ。UI がつながっていない間の `send()` は `kClosed` で失敗し、メッセージは捨てる。
- クライアントの `MessageChannel` は 1 つの接続を表す。切断されたら `on_closed()` を 1 回呼び、以降は使わない。自分で破棄したときは呼ばない。つながり直すときは、コンポジションルートがクライアントを作り直す。接続は、パイプがない間（エンジンの起動中）とビジーの間は、指定した時間まで再試行する。
- `pa-engine` に再接続した `remote-pa` は、UI に全状態を受け取り直させる必要がある。`webui` の `WebUiHost::reload()` でページを読み込み直すと、UI は読み込み後に `hello` を送ってスナップショットを受け取る。いつ再接続するか（エンジンの再起動の待ち方）はコンポジションルートを組み立てるときに決める。

### 送信の非同期化

- `send()` は、接続ごとの送信キューに積んで戻る。書き込みは接続ごとの送信スレッドが行う。
- キューに積まれた未送信のバイト数が 1 MiB を超えたら、相手が受信していないとみなして接続を切る。UI がハングしても、エンジンのコントロールスレッドが書き込みで止まらないようにするため。メーター（30 Hz）を UI が読まなくなっても数秒で上限に達するので、ハングした UI の接続は早めに切れる。切られた UI は、復帰したら再接続してスナップショットから表示し直す。

### WebView のブリッジ

- UI からネイティブ側へは、JUCE のイベント `vocroz.to_engine`、ネイティブ側から UI へはイベント `vocroz.from_engine` を使う。どちらも本文は 1 メッセージ分の JSON の文字列で、ブリッジは中継するだけで中身を読まない（`ui/src/ipc/juce-transport.ts` と同じ値）。
- 起動時の設定（`mode`、`lang`、`join`）は初期化データ（`withInitialisationData`）で渡す（`ui/src/ipc/launch-config.ts`）。
- ページの読み込みが終わる前と、再読み込みの最中に届いたメッセージは捨てる。JUCE は読み込み前のイベントを送れず、UI は読み込み後に `hello` を送ってスナップショットを受け取るので、捨てても表示は欠けない。
- `send()` はどのスレッドからでも呼べ、メッセージスレッドに渡してから WebView に送る。UI からの受信は、メッセージスレッドでリスナーに渡す。
- ネイティブ連携を有効にしているので、リソースプロバイダーのルート以外への移動（リンクのクリックなど）は止める。外部のページに `window.__JUCE__` を触らせないため。
- `ui/dist` は CMake の関数 `vocroz_embed_ui_assets()`（`cmake/EmbedUiAssets.cmake`）でファイルの一覧と内容を C++ の配列に変換し、実行ファイルに埋め込む。リソースプロバイダーは、パスの正規化（`/` は `index.html`、クエリとフラグメントは無視、`..` を含むパスは拒否）と、拡張子からの MIME タイプの決定を行う。これらは JUCE に依存しない純粋なコードにして、Linux の CI でも単体テストする。
- WebView2 のユーザーデータフォルダは、コンポジションルートが `--data-dir` の下に決めて渡す。既定の場所（実行ファイルの隣）はバージョン別フォルダの中で、更新のたびに失われるため。

### WebView2 SDK の取得

- NuGet のパッケージ `Microsoft.Web.WebView2` の 1.0.3912.50 を、`cmake/webview2.cmake` が URL と SHA-256 で固定して取得し、JUCE の `FindWebView2.cmake` が探す場所（`JUCE_WEBVIEW2_PACKAGE_LOCATION`）に展開する。ライセンスは BSD-3-Clause で、AGPL-3.0 と組み合わせて配布できる。
- `WebView2LoaderStatic.lib` を静的にリンクする（`JUCE_USE_WIN_WEBVIEW2_WITH_STATIC_LINKING=1`）。`WebView2Loader.dll` を配布物に加えずに済む。WebView2 の実行環境（Evergreen Runtime）は OS のものを使う。
- JUCE のモジュールのソースは、それをリンクしたターゲットごとにコンパイルされる。複数のアダプターが JUCE を使うと同じシンボルが重複するので、JUCE のモジュールは静的ライブラリ `vocroz::juce` 1 つにまとめてコンパイルし、アダプターはそれをリンクする。

## 理由

- 長さの前置きは、JSON の中身を走査せずに境界がわかり、上限を超える入力をメモリに読み込む前に拒否できる。
- `FILE_FLAG_FIRST_PIPE_INSTANCE` と所有者の確認を両側で行えば、どちらのプロセスが先に起動しても、ほかのユーザーのプロセスとつながらない。ACL だけでは、先に同じ名前で待ち受けられた場合を防げない。
- エンジン主権（AGENTS.md 1.1）のもとでは、正となる状態はエンジンにあり、UI はいつでもスナップショットから表示し直せる。だから、不正なフレームや応答しない UI に対しては、接続を切って作り直すのが最も単純で安全になる。
- サーバー側の `MessageChannel` を UI の再接続にまたがって同じものにすれば、`session` はパイプの接続と切断を意識せず、`hello` に応えるだけで済む。
- WebView2 の SDK を手元の NuGet に入れる手順を省けば、Windows の CI と開発者の手元で、ほかの外部ライブラリと同じく configure だけでビルドできる（`docs/adr/0010-external-libraries.md`）。

## 結果

- `modules/ipc` と `modules/webui` を追加し、`modules/README.md` の表を更新する。AGENTS.md の表（2.1、3.3、4.2）にはすでに行がある。
- `cmake/webview2.cmake` を追加し、`docs/adr/0010-external-libraries.md` の表と CONTRIBUTING.md のライセンス一覧に WebView2 SDK を加える。配布物には WebView2 SDK のライセンス文を同梱する。
- Windows 10 では WebView2 の実行環境が入っていないことがある。インストーラーで確認して入れるかどうかは、インストーラーの作業で決める。
- `remote-pa` に `ui/dist` を埋め込むには、CMake の configure より前に `ui` をビルドしておく必要がある。コンポジションルートを組み立てるときに、Windows の CI に UI のビルドを加える。
