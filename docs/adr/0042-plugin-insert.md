# 0042. プラグインの挿入

- 状態: 採用（2026-11-10）

## コンテキスト

ADR-0024 で、プラグインはグラフの独立したノードとし、挿入位置の結線の間に置くことを決めた。
ADR-0032 で、プラグインの一覧（`PluginCatalog`）と、読み込みのポート（`PluginLoader`）を決めた。
ADR-0041 で、エディターのウィンドウ（`PluginEditorHost`）と、失敗の印（`PluginFault`）を決めた。

ところが、オペレーターがプラグインをチャンネルやバスに挿す経路がまだない。
`session` は挿入の状態を持たず、`pa-engine` はプラグインを読み込まず、UI にも操作がない。
エディターと失敗の通知を使えるようにするには、まず挿入が要る。

決めることは次のとおり。

- 挿入をどのコマンドで表すか
- 読み込み（JUCE のメッセージスレッド）とグラフの差し替えの順序
- スキャンを回すスレッド
- プラグインの状態の保存先

## 決定

### 挿入はルーティングの構成に載せる

- `control-protocol` の `RoutingConfig` に、挿入の一覧 `inserts`（`RoutingInsert`）を足す。
  - `entity_id`: "fx-" で始める。
  - `target`: 挿す先。ストリップ、"master"、バスの entity_id。
  - `plugin_id`: プラグインの記述の識別子（`PluginDescription::identifier`）。
  - 同じ挿す先の挿入は、一覧の順に直列につなぐ。
- 挿入の追加、削除、並べ替えは、ほかのルーティングと同じくステージングして適用する（`stage_routing`、`commit_routing`）。新しいコマンドは作らない。
  - グラフの形を変える操作はステージングにまとめ、検証とループの承認を 1 か所で行うため（ADR-0026）。
  - 1 回の適用で、複数の挿入とセンドの変更を同じグラフの差し替えにまとめられる。
- グラフでの位置（ADR-0024 のとおり）:
  - ストリップ: ソース → 挿入 → ストリップ（フェーダーの前）。
  - Master とバス: Master かバス → 挿入 → 後段のすべて（センド、リミッター、出力）。
- 検証（`routing_validator`）に次を足す。
  - 挿す先が構成かストリップの一覧にある。ない挿入は `UNKNOWN_NODE`。
  - プラグインがプラグインの一覧にある。ない挿入は `UNKNOWN_PLUGIN`（新しい `RoutingIssue`）。
  - 1 つの挿す先に `kMaxInsertsPerTarget`（8）まで、全体で `kMaxInserts`（32）まで。超えたら `TOO_MANY_ITEMS`。
    - 全体の上限は、スナップショットが適用中とステージング中の構成を両方含んでも `kMaxMessageBytes`（64 KiB）に収まる数にする。同じ理由で、プラグインの識別子は 256 バイトまでにする。
  - VSTi（音声入力を持たないプラグイン）は挿入にしない。`UNSUPPORTED_PLUGIN`（新しい `RoutingIssue`）。VSTi は MIDI の送り先で、音源の置き場所は Beta5 の続きで決める。
- 保存（ADR-0033）: Master とバスへの挿入は保存し、ストリップへの挿入は保存しない。ストリップの ID は次の起動では別の参加者を指すためで、センドと同じ扱いにする。
  - 起動時は、プラグインの一覧にないプラグイン（アンインストールしたものなど）の挿入だけを外して戻し、警告をログに残す。1 つのプラグインがないためにルーティング全体を既定の結線に戻さないため。
  - そのため、コンポジションルートは保存したスキャンの記録から作った一覧を、`HostSession::start()` の前に `set_available_plugins()` で渡す。記録を読むだけなのですぐに済み、スキャンは待たない。

### 読み込みとグラフの差し替え

- `session` は挿入ごとに、読み込みの状態（`loading`、`ready`、`failed`）と、グラフに渡す処理と失敗の印を持つ。
- 読み込みは、`session` の新しいポート `PluginRack` に依頼する。`session` はスレッドを知らない。
  - `load(insert_id, ticket, description)`: 読み込みを始める。結果は後で `HostSession::on_plugin_loaded()` に同じ `ticket` で届く。`ticket` は依頼ごとの番号で、外して挿し直した挿入の、前の依頼の遅れて届いた結果を見分けるために使う。
  - `release(insert_id)`: エディターを閉じ、インスタンスを破棄する。
  - `open_editor(insert_id, title)`: エディターを開く。実装の 2 段目で、コマンドと一緒に足す。
  - `pa-engine` が、JUCE のメッセージスレッド（ADR-0039）の上の `PluginLoader` と `PluginEditorHost` で実装する。結果はコントロールスレッドのキューへ戻す。
- 適用の順序:
  1. `commit_routing` で、構成をすぐに適用する。読み込みの済んでいない挿入は、その挿入を通る経路を切ってグラフを作る（無音）。読み込み中に、プラグインを通らない音を出さないためである。
     - ストリップはソースからの経路を切る。ソースのノードは残し、受信ストリームから取り出し続ける。
     - Master とバスは、後段（センド、リミッター、外部出力）を入力のない無音の段から取る。センドをグラフから外すと、センドのフェーダーをミュートすることになり、session の状態とずれるため。
     - 挿す先の挿入のうち 1 つでも済んでいなければ、済んだ挿入も通さない。一部のプラグインだけを通した音も、オペレーターが意図した音ではないため。
  2. 構成をミキサーへ適用してから、新しい挿入の読み込みと、外した挿入の `release()` を依頼する。
     - 処理（`PluginProcessor`）は共有ポインターで、古いグラフが手放すまで生き続ける。`release()` はインスタンスの破棄を依頼するだけで、オーディオスレッドが使っている処理を消さない。
     - 処理の最後の参照がどのスレッドで外れても JUCE のプラグインをメッセージスレッドで破棄するのは、`pa-engine` の `PluginRack`（`EnginePluginRack`）の責務にする。
       - グラフには、インスタンスが持つ処理を指す別の共有ポインター（aliasing constructor）を渡す。その最後の参照が外れたら、削除子がメッセージスレッドへ知らせる。
       - インスタンスは、`release()` 済みで、かつグラフが手放したときに、メッセージスレッドで破棄する。エディターを先に閉じる。
       - 終了時は、オーディオ出力を閉じてから、メッセージスレッドの最後の処理（`JuceMessageThread::stop()` の `last`）ですべてを破棄する。それ以降にグラフが手放しても、知らせない。
  3. 読み込みが済むたびに、同じ構成でグラフを作り直して差し替える。revision は進めない（観測値の変化のため）。
- 読み込みに失敗した挿入は `failed` にし、その経路を無音にしたままにする（フェイルセーフ）。理由（見つからない、作れない、チャンネル構成が合わない）を状態に持つ。
- 処理中の失敗（`PluginFault`）も、同じ `failed` にする（ADR-0041）。失敗を解くのは、挿入を外して挿し直す操作だけにする。
- ミキサーへの受け渡しは、`MixerControl::apply_routing()` に、読み込み済みの挿入（`InsertedPlugin`: entity_id、処理、失敗の印）の一覧の引数を足して行う。
  - 構成と挿入を 1 回の呼び出しで渡し、構成だけが変わって挿入が古いままのグラフを作る瞬間をなくすため。
  - 失敗の印は、読み込みが済んだときに session が挿入ごとに 1 つ作る。session は `tick()` で印を見て、処理中の失敗を拾う。
- ストリップの挿入は、末尾のプラグインの出力のチャンネル数にストリップを合わせる。モノラルの声にステレオのリバーブを挿したとき、左右を保つため。

### スキャン

- `pa-engine` は、プラグインのスキャン専用のスレッドを 1 本持つ。このスレッドが `PluginCatalog` を持ち、起動時に読み込みと再スキャンを行う。
  - ヘルパーの起動にファイルごとに時間がかかり（制限時間 30 秒）、コントロールスレッドでもメッセージスレッドでも、ほかの処理を長く止めるため。
  - 結果（使えるプラグインの一覧と、読み込み不可の記録）は、コントロールスレッドのキューへ戻す。
  - スキャンの記録は `<data-dir>\plugin-catalog.json` に保存する（`persistence` の `JsonPluginCatalogStore`）。設定とは別のファイルにし、バックアップは取らない。壊れていても、スキャンし直せば作り直せるため。
  - 探す場所は、VST3 の標準の場所（`%CommonProgramFiles%\VST3` と `%LOCALAPPDATA%\Programs\Common\VST3`）にする。場所を選ぶ設定は UI の作業と合わせて加える（ADR-0032）。
  - ヘルパーは `pa-engine.exe` と同じフォルダの `pa-plugin-scanner.exe` を使う。起動できなければ、スキャンを中断してエラーをログに残す（ADR-0032）。
  - 終了時は、ファイル 1 つのスキャンが済むまで待ってからスレッドを止める。待つ時間はヘルパーの制限時間が上限になる。途中までの記録は保存せず、次の起動で残りをスキャンする。
- UI からの再スキャンは、新しいコマンド `rescan_plugins` で依頼する。

### UI との形式

- スナップショットに、プラグインの一覧（名前、製造元、識別子、VSTi か）と、スキャンの状態（スキャン中か、読み込み不可のファイル）を足す。
- 挿入ごとの状態（読み込みの状態、失敗の理由、エディターが開いているか）は、挿入の entity_id ごとの状態として送る。
- エディターを開く操作は、新しいコマンド `open_plugin_editor` で依頼する。開けなかったら、エラーコードを返す。

### プラグインの状態の保存

- 挿入ごとに、プラグインの状態（`PluginInstance::save_state()` のバイト列）を親機の設定に保存する。保存するのは、適用したときとセッションの終了時（ADR-0033 と同じ）である。
- 読み込んだ直後に、保存した状態を戻す（`restore_state()`）。戻せなかったら、プラグインの既定の状態のまま使い、警告をログに残す。

## 理由

- **フェイルセーフ**: 読み込み中と失敗したプラグインの経路は無音にする。プラグインで下げていた音量が、素通しで突然戻らないようにするため（ADR-0024）。
- **低遅延**: 読み込みはオーディオスレッドの外で行い、グラフはこれまでどおりスワップで差し替える。オーディオスレッドが読み込みを待つことはない。
- **テスタビリティ**: `session` は `PluginRack` のポートだけを見るので、読み込みの成功、失敗、遅れをフェイクで再現して単体テストできる。
- **既存の仕組みに載せる**: 挿入はグラフの形の変更なので、ルーティングのステージング、検証、保存、復元をそのまま使える。

## 結果

- `RoutingConfig` の形が変わるので、`control-protocol` と `ui/src/ipc/` を同じ PR で変える（AGENTS.md 4.4）。
- `MixerControl::apply_routing()` の引数が増え、`HostSession::Ports` に `PluginRack` が増えるので、すべての実装と生成箇所（`pa-engine`、`tests/harness`、各テスト、フェイク）を同じ PR で直す。
- JUCE を使わない `pa-engine` のビルドは、プラグインを読み込まない `PluginRack`（`NoPluginRack`）を渡す。一覧を渡さないので、検証で挿入はすべて `UNKNOWN_PLUGIN` になる。
- 実装は次の順に分ける。
  1. 構成と検証、`session` の挿入の状態、`PluginRack` のポート、ミキサーのグラフへの組み込み。
  2. `pa-engine` での `PluginRack` の実装（メッセージスレッド）、スキャンのスレッドと記録の保存。
  3. コマンド（`rescan_plugins`、`open_plugin_editor`）と、スナップショットのプラグインの一覧、スキャンの状態、挿入ごとの状態。
  4. UI（挿入の操作、状態の表示、失敗のトースト、エディターを開くボタン）。
  5. プラグインの状態の保存と復元。
