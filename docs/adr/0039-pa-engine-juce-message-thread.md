# 0039. pa-engine に JUCE のメッセージスレッドを置く

- 状態: 採用（2026-11-09）

## コンテキスト

JUCE 9 の MIDI は、次の処理をメッセージスレッドでしか扱わない（`JUCE_ASSERT_MESSAGE_THREAD`）。

- 入力ポートの一覧。メッセージループで非同期に更新されるキャッシュから返る
- ポートの開閉
- 切断の通知（`ump::DisconnectionListener`）

`docs/adr/0029-midi-and-vsti.md` のとおり、親機の MIDI 機器は `pa-engine` の中で `MidiInputQueue` に積む。ところが `pa-engine` はコンソールのプロセスで、JUCE のメッセージループを回していない。
プラグインのエディターのウィンドウ（`PluginEditorHost`、`docs/adr/0009-beta-module-layout.md`）も、JUCE のメッセージスレッドを前提にしている。

一方、`pa-engine` のコントロールスレッドは IPC、セッションの状態遷移、設定の永続化を担う（AGENTS.md 2.3）。
コントロールスレッドに JUCE のメッセージループを兼ねさせると、2 つの問題が起きる。

- プラグインのエディターや MIDI のドライバーが JUCE のメッセージを長く止めると、UI のコマンドの適用や再接続の処理が遅れる。
- 逆に、セッションの処理が長いと、エディターの描画と MIDI の切断の通知が遅れる。

子機（`remote-pa`）は UI のホストのために、もともと JUCE のメッセージループを回している。

## 決定

- `pa-engine` のコンポジションルートは、JUCE のメッセージスレッドを専用に 1 本持つ。そのスレッドで `juce::ScopedJuceInitialiser_GUI` を作り、`MessageManager::runDispatchLoop()` を回す。コントロールスレッドとは分ける。
- このスレッドは、`device` の MIDI 入力（一覧、開閉、切断の通知）と、`plugin-host` のエディターのウィンドウで共有する。アダプターごとに別のメッセージループを持たない。JUCE の `MessageManager` はプロセスに 1 つしか持てないため。
- スレッドの間の受け渡し:
  - コントロールスレッドからの依頼（MIDI のポートを開く、閉じる、一覧を取る、エディターを開く、閉じる）は、`MessageManager::callAsync` でメッセージスレッドへ渡す。
  - 結果と通知（開けなかった、抜去された、エディターが閉じられた）は、コントロールスレッドのキューへ戻す。メッセージスレッドから `session` を直接呼ばない（`HostSession` はコントロールスレッドからだけ呼ぶ）。
  - MIDI の受信のコールバックは JUCE の受信スレッドで呼ばれる。これまでどおり `MidiInputQueue`（SPSC）でオーディオスレッドへ渡し、メッセージスレッドもコントロールスレッドも経由しない。
- 子機（`remote-pa`）は、既存のメッセージループをそのまま使う。新しいスレッドは作らない。
- 終了の順序: 次の順で止める。
  1. メッセージスレッドの上で MIDI 入力を閉じ、エディターを破棄する。
  2. `MessageManager::stopDispatchLoop()` でループを抜け、`ScopedJuceInitialiser_GUI` を破棄する。
  3. スレッドを join する。

  MIDI のポートとエディターは JUCE の資源を持つので、JUCE を終了する前に、作ったスレッドの上で破棄する必要がある。

## 理由

- **待ち合いを作らない**: 合奏中は、UI のコマンドと再接続をすぐに適用したい。JUCE のメッセージ（エディターの描画、ドライバーの通知）とセッションの処理が互いを待たないよう、スレッドを分ける。
- **メッセージループは 1 つ**: JUCE の `MessageManager` は、プロセスに 1 つのシングルトンである。MIDI とエディターで別々に持つことはできない。
- **低遅延の経路は変えない**: 打鍵からオーディオスレッドまでの経路（JUCE の受信スレッド → `MidiInputQueue` → オーディオスレッド）にメッセージスレッドを挟まない。メッセージスレッドを通るのは、開閉と通知だけにする。

## 結果

- `pa-engine` には、AGENTS.md 2.3 のスレッドに「JUCE のメッセージスレッド」が 1 本増える。
- `device` の `make_juce_midi_input()` と `make_juce_midi_device_catalog()` は、メッセージスレッドから呼ぶ前提になる。
- `pa-engine` の実際の組み立ては、E1 の続きで行う。メッセージスレッドを立て、MIDI を `MidiInputQueue` とグラフの MIDI ソースにつなぎ、抜去の通知で `request_panic()` を呼ぶ。プラグインのエディターも、このスレッドに載せる。
- メッセージスレッドの処理が止まっても、オーディオと MIDI の受信は止まらない。抜去の通知とエディターだけが遅れる。
