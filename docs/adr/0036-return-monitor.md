# 0036. 返送モニター（Minus-Me）のミックス、下りストリーム、返送ミュート

- 状態: 採用（2026-11-09）

## コンテキスト

Beta1 の返送モニターは、親機のミックスを子機へ送り返し、出演者が親機のミックスを聞きながら演奏できるようにする機能である（合奏の前提）。
仕様は次のことを求めている。

- 子機ごとに、その子機自身のマイクを除いたミックス（Minus-Me）を作って送り返す。ハウリングとエコーを防ぐため
- 返送は初期値で OFF（`return_muted` = true）。設定と解除は親機だけができる
- 返送を OFF かミュートにしている間は、親機から子機への音声の送信そのものを止める（方向別のデータフロー規則）
- 停止と再開の判定には、子機の送信ミュートと同じく世代番号（epoch）を使い、制御メッセージとメディアの到着順の逆転で誤判定しない

ADR-0009 で、ミックスは `audio-core`、下りストリームは `transport`、返送の ON / OFF と送信を止める判断は `session`、子機の再生は `client-desktop` と決めている。
ここでは、それぞれの形と、モジュールの間の受け渡しを決める。

## 決定

### Minus-Me のミックス（audio-core）

- 子機 1 台ぶんの返送を、グラフのノードとして組む。`add_minus_me_returns()` が、返送ごとに「ミックスの候補のポストフェーダー → 安全リミッター → 返送タップ」を `GraphDescription` に足す。
- 返送タップ（`NodeKind::kReturnTap`）は新しいノードの種類で、ステレオの入力を加算してモノラルにダウンミックスし（L と R の平均）、`AudioSink` ポートへ 1 ブロックずつ渡す。出力を持たないので、後段へはつなげない。
- ミックスの候補（親機のミックスに入るストリップなど）と、その子機自身の入力（その子機のストリップ。複数入力ならすべて）を呼び出し側が渡す。`add_minus_me_returns()` は、子機自身の入力と、子機自身の入力から結線をたどって届くノード（その子機の声を含むバス）を候補から外す。呼び出し側が候補にバスを含めても、自分の声が返送に入らないことを `audio-core` が保証する。
- 返送はポストフェーダーで取る。オペレーターが作ったメインのバランスのまま、自分の声だけを抜いたミックスにする（チャンネルミュートしたチャンネルは返送にも入らない）。
- 返送の経路にも安全リミッターを通す。返送は出演者の耳に直接届く出力なので、メインの出力と同じく過大な音を出さない。
- `pa-engine` の候補は、Master へ入る信号（ストリップと、Master へ送るバスと遅延ノード）にする。返送は Master のフェーダーとミュートを通さない。Master はハウスの出力の操作で、オペレーターが PA を絞っても出演者のモニターまで止めるものではないため。キューやモニター用のバス（Master へ送らないもの）は返送に入らない。
- `EngineMixer::attach_return()` で、子機との接続ごとに、返送の渡し先（`AudioSink`）とその子機のストリップの一覧をつなぐ。子機の入力が増減したら、同じキーで一覧を付け替える。

### 下りストリーム（transport）

- ワイヤーフォーマットは上り（子機 → 親機）と同じ `MediaPayload`（ADR-0014）を使う。ストリーム ID は向きごとに別の名前空間とし、返送は下りのストリーム ID 0 にする。上りのストリーム ID（子機が 0 から振る）とは衝突しない。
- 親機のエンコードは `MediaStreamEncoder` が行う。`AudioSink` を実装し、オーディオスレッドで 1 フレームぶん溜まるごとに Opus でエンコードして、`MediaFrameSink` ポートへ `MediaFrame` を渡す（受け取った側がネットワークのスレッドで暗号化して送る）。ミュート、世代番号、送信レベルはコントロールスレッドから SPSC キューで受け取る。
- ミュートしたら、ゲインランプで無音にしてから送信を止める。止めている間もタイムスタンプは実時間どおりに進め、再開後のフレームは新しい世代番号を運ぶ。子機の送信側（`client-desktop` の `CaptureProcessor`）と同じ規則なので、同じクラスを子機の送信にも使える形にしておく。
- エンコードはオーディオスレッドで行う（AGENTS.md 2.3）。追加のバッファリングを入れないためで、ミュート中はエンコードしないので、OFF の子機のぶんの負荷はかからない。

### 返送ミュート（session と control-protocol）

- OFF とミュートは同じ状態として扱い、ストリップの `return_muted` 1 つで表す。どちらも送信を止めるという点で振る舞いが同じで、UI の操作を 1 つにした方が本番中に迷わないため。初期値は true（初期ミュート）。
- 返送は子機 1 台に 1 本なので、子機が複数の入力を送っているとき（`docs/adr/0035-client-input-expansion.md`）は、その子機のストリップがすべて同じ `return_muted` と世代番号を持つ。どのストリップから切り替えても子機全体に効き、後から足した入力のストリップも今の状態を引き継ぐ。
- UI は `set_return_mute`（対象はチャンネルストリップ）で切り替える。ストリップの revision を進め、ACK を受けてから表示を変える。
- `session` は解除のたびに世代番号を 1 増やし、`PeerLink::set_return_mute()` で下りストリームの送信側（エンコーダーの組み立て）へ、制御メッセージ `ReturnMuteNotice`（`muted`、`epoch`）で子機へ知らせる。再接続で元のストリップに戻ったときも、承認の後に今の状態を送り直す。
- 子機の `session` は `ReturnMuteNotice` を `HostLink::apply_return_mute()` で受信側（ジッターバッファの前の世代番号の判定）へ渡し、子機のスナップショットの `return_muted` に写す。子機からは返送を解除できない（子機から親機へのメッセージに返送を操作するものはない）。

## 理由

- ミックスをグラフのノードで組めば、ルーティング、PDC、グラフのスワップ、RealtimeSanitizer の検査をそのまま使える。子機ごとに別のミキサーを持つ方式は、フェーダーとメーターの状態を二重に持つことになる。
- 「自分の声を含むノードを外す」判定を `audio-core` に置けば、ルーティングで作ったバスを返送に含めても、自分の声が回り込まないことを単体テストで確かめられる。呼び出し側に任せると、ルーティングの構成が変わるたびに判定がずれうる。
- 下りにも上りと同じ形式と世代番号を使えば、子機の受信は親機の受信と同じ部品（`SendMuteTracker`、`SignalMonitor`、`PlayoutStream`）で組める。

## 結果

- 返送のレベル（子機ごとの返送の音量）は持たない。必要になったら、返送ごとのバスのフェーダーとして足す。
- 返送の音を子機が送信のソースに選んだ場合のルートガード（アプリ音声のループバックで返送音を拾う場合）は、ループバックの収集（B1c）と合わせて子機側で入れる。
- 子機の送信側の `CaptureProcessor` は、ミュートとエンコードの規則が `MediaStreamEncoder` と同じなので、子機の入力拡張（B1c）の後で `MediaStreamEncoder` を使う形にそろえる。
- 親機の送信（`pa-engine` の子機との接続の組み立て）と、子機の再生（出力デバイスの選択、ジッターバッファ、低遅延の出力）、画面は続きの PR で組み立てる。
