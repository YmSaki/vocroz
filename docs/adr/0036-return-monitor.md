# 0036. 返送モニター（Minus-Me）のミックス、下りストリーム、返送ミュート

- 状態: 採用（2026-11-09）

## コンテキスト

Beta1 の返送モニターは、親機のミックスを子機へ送り返し、出演者が親機のミックスを聞きながら演奏できるようにする機能である（合奏の前提）。
仕様は次のことを求めている。

- 子機ごとに、その子機自身のマイクを除いたミックス（Minus-Me）を作って送り返す。ハウリングとエコーを防ぐため
- 返送は初期値で OFF（`return_muted` = true）。設定と解除は親機だけができる
- 返送を OFF かミュートにしている間は、親機から子機への音声の送信そのものを止める（方向別のデータフロー規則）
- 停止と再開の判定には、子機の送信ミュートと同じく世代番号（epoch）を使い、制御メッセージとメディアの到着順の逆転で誤判定しない

ADR-0009 で、ミックスは `audio-core`、下りストリームは `transport`、返送の ON / OFF と送信を止める判断は `session`、子機の再生は `client-desktop` と決めている。
ここでは、それぞれの形と、モジュールの間の受け渡しを決める。

## 決定

### Minus-Me のミックス（audio-core）

- 子機 1 台ぶんの返送を、グラフのノードとして組む。`add_minus_me_returns()` が、返送ごとに「ミックスの候補のポストフェーダー → 安全リミッター → 返送タップ」を `GraphDescription` に足す。
- 返送タップ（`NodeKind::kReturnTap`）は新しいノードの種類で、ステレオの入力を加算してモノラルにダウンミックスし（L と R の平均）、`AudioSink` ポートへ 1 ブロックずつ渡す。出力を持たないので、後段へはつなげない。
- ミックスの候補（親機のミックスに入るストリップなど）と、その子機自身の入力（その子機のストリップ。複数入力ならすべて）を呼び出し側が渡す。`add_minus_me_returns()` は、子機自身の入力と、子機自身の入力から結線をたどって届くノード（その子機の声を含むバス）を候補から外す。呼び出し側が候補にバスを含めても、自分の声が返送に入らないことを `audio-core` が保証する。
- 返送はポストフェーダーで取る。オペレーターが作ったメインのバランスのまま、自分の声だけを抜いたミックスにする（チャンネルミュートしたチャンネルは返送にも入らない）。
- 返送の経路にも安全リミッターを通す。返送は出演者の耳に直接届く出力なので、メインの出力と同じく過大な音を出さない。
- `pa-engine` の候補は、Master へ入る信号（ストリップと、Master へ送るバスと遅延ノード）にする。返送は Master のフェーダーとミュートを通さない。Master はハウスの出力の操作で、オペレーターが PA を絞っても出演者のモニターまで止めるものではないため。キューやモニター用のバス（Master へ送らないもの）は返送に入らない。
- `EngineMixer::attach_return()` で、子機との接続ごとに、返送の渡し先（`AudioSink`）とその子機のストリップの一覧をつなぐ。子機の入力が増減したら、同じキーで一覧を付け替える。

### 下りストリーム（transport）

- ワイヤーフォーマットは上り（子機 → 親機）と同じ `MediaPayload`（ADR-0014）を使う。ストリーム ID は向きごとに別の名前空間とし、返送は下りのストリーム ID 0 にする。上りのストリーム ID（子機が 0 から振る）とは衝突しない。
- 親機のエンコードは `MediaStreamEncoder` が行う。`AudioSink` を実装し、オーディオスレッドで 1 フレームぶん溜まるごとに Opus でエンコードして、`MediaFrameSink` ポートへ `MediaFrame` を渡す（受け取った側がネットワークのスレッドで暗号化して送る）。ミュート、世代番号、送信レベルはコントロールスレッドから SPSC キューで受け取る。
- ミュートしたら、ゲインランプで無音にしてから送信を止める。止めている間もタイムスタンプは実時間どおりに進め、再開後のフレームは新しい世代番号を運ぶ。子機の送信側（`client-desktop` の `CaptureProcessor`）と同じ規則なので、同じクラスを子機の送信にも使える形にしておく。
- エンコードはオーディオスレッドで行う（AGENTS.md 2.3）。追加のバッファリングを入れないためで、ミュート中はエンコードしないので、OFF の子機のぶんの負荷はかからない。

### 親機の送信（pa-engine と transport）

- 親機は子機との接続ごとに `PeerPacketSender`（`transport`）を持つ。制御パケットの平文（コントロールスレッドの信頼制御層から）とエンコード済みのフレーム（オーディオスレッドの `MediaStreamEncoder` から）を SPSC キューで受け取り、送信スレッドがまとめて暗号化して送る。`PacketSealer` はメディアと制御で同じシーケンス番号を使い、1 つのスレッドからしか使えないため、これまでコントロールスレッドで暗号化していた制御パケットも送信スレッドへ移す。子機の送信（`client-desktop` の `PacketSender`）と同じ規則。
- 送るものを入れた側は `SendNotifier`（`transport` のポート）で送信スレッドを起こす。実装の `SendWakeup` は子機の送信スレッドと共有するので、`client-desktop` から `transport` へ移す。合図で起きるので、ポーリングの周期ぶんの遅延を音声に足さない。
- 送信スレッドは接続ごとに 1 本立てる（`pa-engine` の `ThreadPeerSendScheduler`）。全接続で 1 本を共有しない。
- `HostPeerLinks` は、承認（`admit()`）で返送のエンコーダーを `EngineMixer::attach_return()` につなぎ（キーは接続）、接続を閉じるときに外す。`set_return_mute()` はエンコーダーへ設定（ミュート、世代番号、送信レベル 1）を渡す。エンコーダーと送信待ちはミキサーの古いグラフからも参照されるので、接続を破棄しても参照が外れるまで保ち、送信スレッドはコントロールスレッドで止める。
- 終了時は、オーディオ出力を閉じてから送信スレッドを止め、その後で UDP のソケットを閉じる。

### 返送ミュート（session と control-protocol）

- OFF とミュートは同じ状態として扱い、ストリップの `return_muted` 1 つで表す。どちらも送信を止めるという点で振る舞いが同じで、UI の操作を 1 つにした方が本番中に迷わないため。初期値は true（初期ミュート）。
- 返送は子機 1 台に 1 本なので、子機が複数の入力を送っているとき（`docs/adr/0035-client-input-expansion.md`）は、その子機のストリップがすべて同じ `return_muted` と世代番号を持つ。どのストリップから切り替えても子機全体に効き、後から足した入力のストリップも今の状態を引き継ぐ。
- UI は `set_return_mute`（対象はチャンネルストリップ）で切り替える。ストリップの revision を進め、ACK を受けてから表示を変える。
- `session` は解除のたびに世代番号を 1 増やし、`PeerLink::set_return_mute()` で下りストリームの送信側（エンコーダーの組み立て）へ、制御メッセージ `ReturnMuteNotice`（`muted`、`epoch`）で子機へ知らせる。再接続で元のストリップに戻ったときも、承認の後に今の状態を送り直す。
- 子機の `session` は `ReturnMuteNotice` を `HostLink::apply_return_mute()` で受信側（ジッターバッファの前の世代番号の判定）へ渡し、子機のスナップショットの `return_muted` に写す。子機からは返送を解除できない（子機から親機へのメッセージに返送を操作するものはない）。

### 子機の受信と再生（client-desktop と session）

- 子機は、鍵交換の後のパケットをネットワーク受信スレッドで復号する（`client-desktop` の `HostReceivePath`）。これまで子機はすべてのパケットをコントロールスレッドへ渡して復号していた（`docs/adr/0030-remote-pa-assembly.md`）が、返送をコントロールスレッドの周期（10 ms）を待たせると、そのぶん届く時刻が揺れてジッターバッファが深くなるため、受信スレッドのままジッターバッファへ入れる。親機の受信（`pa-engine` の `PeerReceivePath`）と同じ形である。
  - ハンドシェイクの応答はこれまでどおり `PeerInbox` でコントロールスレッドへ渡し、鍵交換は `HostConnection` が行う。制御パケットの平文と、認証済みのパケットの送信元の変化は、SPSC キューでコントロールスレッドへ渡す。死活監視は、受信スレッドが数えた認証済みのパケットの数をコントロールスレッドが見て記録する。
  - 受信方向の復号器（`PacketOpener`）はムーブしかできず SPSC キューに載らないので、置き場の配列を持ち、置き場の番号を SPSC キューで渡して所有を移す。受信スレッドが手放した番号はキューで返し、コントロールスレッドが片づける。受信スレッドの状態はすべて `HostReceivePath` の中にあり、`HostConnection` を指さないので、終了の順序にかかわらず受信スレッドが破棄済みのものを触らない。
  - 接続には番号を振り、受信スレッドからの出来事と、返送ミュートの通知がどの接続のものかを見分ける。
- 返送のフレームは、`SendMuteTracker` で返送ミュートの世代番号を判定してからジッターバッファへ入れる。ミュート前とミュート中の世代のフレームは捨てる。
- 返送のジッターバッファ（`PlayoutStream`）は子機に 1 つで、起動から終了まで使う。設定は低遅延プロファイル（最小 10 ms、上限 20 ms）のモノラル。
  - 親機の世代番号は接続をまたいで続くが、メディアのタイムスタンプは接続ごとに 0 から始まる。そのため、子機はジッターバッファへ渡す区間の番号を自分で持ち、接続を付け替えたときと返送が解除されたときに進める。親機の世代番号のまま渡すと、再接続のあとのフレームを古いものとして捨ててしまう。
- 出力デバイスのオーディオスレッドが `ReturnPlayer` を描画のコールバックとして呼び、ジッターバッファから取り出したモノラルの返送を、デバイスのすべてのチャンネル（ヘッドホンの両耳）に書く。返送が届いていない間は無音を書く。
- 返送を鳴らす出力デバイスは出演者が選ぶ。コマンドは親機と同じ `select_output`（対象は子機の entity）で、選んだデバイスは子機の設定（`ClientSettings.output_device_id`）に保存し、起動時に開き直す。初期値は「鳴らさない」。
  - `session` の `ClientSession` は、親機と同じ `OutputDeviceControl` ポートで出力を開き、`client-desktop` の `ReturnOutputDevices` が `AudioDeviceCatalog` と出力を開くポートで実装する。
  - 開けなければ `DEVICE_UNAVAILABLE` で拒否し、別のデバイスへは切り替えない。抜去されたら出力を閉じ、選んだ ID を残して `output_missing` にし、警告の通知（`return_output_lost`）を出す。抜去は観測値なので revision は進めない。
  - 出力を選んでも `return_muted` は変わらない。返送を送るかは親機が決める。
- 子機の画面では、返送の出力デバイスを選び、親機が返送を送っているかを表示する。返送の切り替えは親機のチャンネルストリップに置く。

## 理由

- ミックスをグラフのノードで組めば、ルーティング、PDC、グラフのスワップ、RealtimeSanitizer の検査をそのまま使える。子機ごとに別のミキサーを持つ方式は、フェーダーとメーターの状態を二重に持つことになる。
- 「自分の声を含むノードを外す」判定を `audio-core` に置けば、ルーティングで作ったバスを返送に含めても、自分の声が回り込まないことを単体テストで確かめられる。呼び出し側に任せると、ルーティングの構成が変わるたびに判定がずれうる。
- 下りにも上りと同じ形式と世代番号を使えば、子機の受信は親機の受信と同じ部品（`SendMuteTracker`、`SignalMonitor`、`PlayoutStream`）で組める。
- 送信スレッドを接続ごとに分けるのは、ある子機への送信がソケットの送信で詰まったとき（送信バッファの満杯など）に、他の子機への返送まで遅らせないため。1 本を共有すると、詰まった接続のぶんだけ全員の返送が遅れ、低遅延の要件を 1 台の回線が崩しうる。子機の数（数台から十数台）なら、ほとんど眠っているスレッドがその数だけ増えても負荷は小さい。接続ごとの暗号化の状態（`PacketSealer`）を 1 本のスレッドに閉じ込められるので、スレッド間の受け渡しも SPSC キューだけで済む。
- 送信スレッドを差し替えられるポート（`PeerSendScheduler`）にするのは、テストで送信待ちに入ったその場で送り、送ったデータグラムを決定的に確かめるため。
- 子機の出力デバイスの選択に親機と同じ `select_output` と `OutputDeviceControl` を使うのは、「開けなければ別のデバイスへ切り替えない」「抜去されたら ID を残して選び直しを待つ」という規則が親機の出力と同じで、画面の部品とテストの考え方もそろうため。
- 返送のジッターバッファを接続ごとに作り直さず 1 つにするのは、オーディオスレッドが読むストリームを付け替える仕組み（読み終わったことの確認）を持たずに済むため。区間の番号を進めれば、`PlayoutStream` は新しい区間として溜め直す。

## 結果

- 返送のレベル（子機ごとの返送の音量）は持たない。必要になったら、返送ごとのバスのフェーダーとして足す。
- 返送の音を子機が送信のソースに選んだ場合のルートガード（アプリ音声のループバックで返送音を拾う場合）は、ループバックの収集（B1c）と合わせて子機側で入れる。
- 子機の送信側の `CaptureProcessor` は、ミュートとエンコードの規則が `MediaStreamEncoder` と同じなので、子機の入力拡張（B1c）の後で `MediaStreamEncoder` を使う形にそろえる。
- 片道遅延の実測値の表示は続きの PR で組み立てる。
- 子機のネットワーク受信スレッドが復号を行うようになり、`docs/adr/0030-remote-pa-assembly.md` のスレッドの表のうち、コントロールスレッドの「受信の復号」とネットワーク受信スレッドの「受信の振り分けだけ」は、この ADR の「子機の受信と再生」のとおりに変わる。
- 接続ごとに送信スレッドが 1 本増える。子機の上限（`kMaxPeerConnections`）を大きく引き上げるときは、共有のスレッドプールへの切り替えを検討する。
