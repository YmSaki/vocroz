# 0008. 実行時の振る舞い（電源、スケジューリング、クラッシュ、ファイアウォール、ディスプレイ）

- 状態: 採用（2026-11-07）

## コンテキスト

仕様書は UI の解像度と DPI、フェーダーのキーボード操作、UI とエンジンのクラッシュ時の振る舞い、VST のクラッシュ隔離を定めている。
一方で、本番の数時間を止まらずに動かすための OS との付き合い方（スリープ、スレッドの優先度、クラッシュ時の情報収集、ファイアウォール）は決まっていない。
どれも、決めずに実装すると担当者ごとに違う対処になり、環境を汚す方向（管理者権限、システム全体の設定変更）に流れやすい。

## 決定

- **スリープの抑止**: セッションが `ACTIVE` の間だけ、`SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` でシステムのスリープを抑止する。画面のスリープは抑止しない。セッション終了とプロセス終了で必ず解除する。電源プランなどシステムの設定は変えない。
- **オーディオスレッドのスケジューリング**: オーディオスレッドは MMCSS の「Pro Audio」タスクに登録する（`AvSetMmThreadCharacteristics`）。プロセスの優先度クラスやシステム全体のタイマー分解能は変えない。
- **クラッシュ時の情報**: 未処理の例外ではミニダンプ（`MiniDumpWithDataSegs` 相当の最小限）を `<data-dir>\crash\` に書き、最新の 5 件だけを残す。ダンプは自動送信せず、利用者が診断レポートに含めるかを選ぶ。ダンプには音声バッファや鍵が含まれうるので、診断レポートに含める前にその旨を表示する。
- **エンジンの再起動**: `pa-engine` が異常終了したら、`remote-pa` が通知を出し、利用者の操作で再起動する。再起動後は全チャンネルと Master をミュートした状態から始める。自動で無限に再起動しない。
- **ファイアウォール**: インストーラーとアプリはファイアウォールの規則を追加しない（管理者権限が必要で、環境を汚すため）。NAT 越えは子機と親機の双方から先に UDP を送るホールパンチングで行い、受信だけを待つ待ち受けポートを前提にしない。Windows がファイアウォールの確認ダイアログを出した場合に備え、接続できないときの画面にその確認方法を案内する。
- **ディスプレイ**: Per-Monitor DPI Awareness V2 で動かし、モニター間の移動で表示倍率が変わっても崩れないようにする。ウィンドウの位置とサイズはモードごとに保存し、保存先のモニターがなくなっていれば主モニターに戻す。
- **オフライン**: ランデブーサーバーに届かないときは、セッションの作成と参加だけを不可とし、ミキサーやローカルの入出力の設定は使えるようにする。更新確認の失敗は通知せず、ログにだけ残す。

## 理由

- 本番中のスリープ、オーディオスレッドの優先度不足、原因のわからないクラッシュは、合奏の用途では致命的で、利用者の側では対処できない。
- どの対処も、プロセスが動いている間だけ有効で、終われば元に戻る API に限った。システムの設定、管理者権限、常駐を使わないので、環境を汚さない原則と両立する。
- エンジンを自動で再起動し続けると、原因が解消しないまま音が出たり止まったりを繰り返す。利用者の操作を挟むほうが本番では安全である。

## 結果

- スリープの抑止とクラッシュハンドラーは `pa-engine` と `remote-pa` のアダプター（各アプリの `src/win/`）に置く。MMCSS への登録は `device` のアダプターで、オーディオスレッドの開始時に行う。
- 受け入れテストに、セッション中にスリープしないこと、エンジンを強制終了したあとミュート状態で再起動できること、を加える。
