# 0030. remote-pa の組み立て（子機モードのスレッドと送信の経路、親機モードのエンジンへの接続）

- 状態: 採用（2026-11-09）

## コンテキスト

`remote-pa` は起動ごとに親機モードか子機モードに固定する（`docs/adr/0005-ui-juce-webview.md`、`docs/adr/0007-launch-interface.md`）。
子機モードは 1 つのプロセスで、UI（`webui`）、キャプチャ（`device` の `AudioInput`）、エンコードと暗号化（`transport`）、NAT 越え（`network`）、状態の正（`session` の `ClientSession`）をつなぐ。
各モジュールの部品はそろったが、次の点は決まっていなかった。

- 子機モードのコントロールスレッドをどれにするか。`webui` は UI からの受信を JUCE のメッセージスレッドで渡す（`docs/adr/0020-ipc-pipe-and-webui-bridge.md`）。
- 送信方向の `PacketSealer` は 1 つのスレッドからしか使えない（メディアと制御で同じシーケンス番号を使う）。一方で、オーディオスレッドではソケットへの送信ができず（AGENTS.md 第 9 節）、制御メッセージはコントロールスレッドの信頼制御層が作る。
- 親機モードで `pa-engine` をいつ起動し、どうつなぎ直すか。
- ランデブーサーバーの場所をどこで決めるか。

## 決定

### 子機モードのスレッド

| スレッド | 処理 | 他のスレッドとの受け渡し |
| --- | --- | --- |
| コントロールスレッド（JUCE のメッセージスレッド） | `ClientSession`、UI との変換（`UiBridge`）、親機への接続（`HostConnection`: ランデブー、Noise_IK、受信の復号、信頼制御層、死活監視、再接続のバックオフ） | 下の各キュー |
| オーディオスレッド（WASAPI のキャプチャ） | 送信レベルと送信ミュートのゲインランプ、5ms フレームへの蓄積、Opus のエンコード（`CaptureProcessor`） | 設定は SPSC キューで受け取り、エンコード済みのフレームは SPSC キューで送信スレッドへ渡す。入力のピークはアトミック変数で返す |
| 送信スレッド | メディアと制御のパケットの暗号化と送信（`PacketSender`） | フレーム、制御パケットの平文、送信先の切り替えを、それぞれ SPSC キューで受け取る |
| ネットワーク受信スレッド（Winsock） | 受信の振り分けだけ（`ReceiveRouter`、`PeerInbox`） | ランデブーメッセージと親機のパケットを SPSC キューでコントロールスレッドへ渡す |
| HTTPS の作業用スレッド（`network`） | 招待コードの解決 | 結果を固定長の形で SPSC キューに入れ（`InviteInbox`）、コントロールスレッドが取り出す |

- 送信スレッドは、送るものを入れた側が鳴らす合図（`std::atomic` の `notify_one()`）で起き、送信待ちを空にして眠る。周期で起こすと、その周期ぶんの遅延が音声に足されるため。合図はアトミックな加算と起床だけで、オーディオスレッドをブロックしない。
- 送信方向の `PacketSealer` は送信スレッドだけが持つ。接続（ハンドシェイク）ごとに `SendPath`（暗号化とソケット）を作り、所有権ごと送信スレッドへ渡す。古い送信先は送信スレッドが破棄する（オーディオスレッドではないので解放してよい）。
- 制御パケットの平文には、入れたときの送信先の世代を付ける。張り直す前の信頼制御層の平文を新しい鍵で送ると、親機の新しい信頼制御層が知らない連番を受け取るため、世代の違う平文は捨てる。
- `HostConnection` は、`ClientSession` からの要求（`connect()`、`reconnect()`、`close()`）を次の `poll()` の先頭で反映し、結果の通知を `poll()` の最後にまとめて渡す。通知の中から `session` が `close()` を呼んでも、処理中の接続を壊さないため。
- 再接続は `transport::ReconnectBackoff`（1、2、4、8、15 秒）の間隔で、ランデブーから鍵交換までやり直す。再接続中の失敗は `session` に知らせず試し続け、諦める時刻は `session` の再接続の猶予が決める。最初の接続の失敗は、原因（サーバーに届かない、親機が登録していない、NAT 越えが成立しない）によらず `UNREACHABLE` で知らせる。出演者にできること（回線と招待を確かめる）が同じため。
- 送信ミュート中は、ゲインランプで 0 まで下げきった後のフレームを送らない。タイムスタンプは送らないフレームでも実時間どおりに進める。
- 複数チャンネルの入力デバイスでは 1 チャンネル目だけを送る。入力チャンネルの選択は Beta で加える。
- 入力のメーターは、送信レベルと送信ミュートを掛ける前のピークを 50ms ごとに `meters` で送る。送信ミュート中も、出演者がマイクの入りを確かめられるようにするため。
- 入力なしの間はオーディオスレッドが設定を取り出さないので、新しいデバイスで始める前に `CaptureProcessor::restart()` で最新の設定（ミュートを含む）から始め直す。デバイスが動いている間に設定のキューが溢れたときは、コントロールスレッドの周期で渡し直す。

### 置き場所

- OS に依存しない組み立ては `apps/client-desktop/src/`（`ClientRuntime` とその部品）に置き、フェイクで単体テストする（`apps/client-desktop/tests/`）。
- WebView、WASAPI、Winsock、WinHTTP をつなぐコンポジションルートは、同じ `client-desktop` に Windows と JUCE のときだけビルドする形で置く。

### 親機モードとエンジンの起動

`pa-engine` の起動の取り決めは `docs/adr/0028-engine-assembly.md` と合わせた。

1. `remote-pa`（親機モード）は起動時に `ipc` のクライアントでパイプへ接続を試み、つながればそのまま使う（再アタッチ）。
2. つながらなければ、自分と同じフォルダの `pa-engine` を `--data-dir=<同じ値> --log-level=<同じ値>` で起動し、パイプにつながるまで再試行する。つながった時点を準備完了とみなす。`pa-engine` が終了コード 3（既に動いている）で終わった場合も、既存のエンジンへの接続を続ける。
3. 接続が切れたら同じ手順でつなぎ直し、つながったら `WebUiHost::reload()` で UI に `hello` をやり直させる。
4. `remote-pa` を閉じても `pa-engine` は止めない。本番中に UI だけを再起動しても音を止めないため。`pa-engine` はセッションも UI もない状態が 30 秒続いたときだけ自分で終わる。

### ランデブーサーバーの場所

- ランデブーサーバーはベース URL（例: `https://rendezvous.example`）1 つで指定する。招待の HTTPS はこの URL を、UDP のランデブー（3478 番）はこの URL のホスト名を解決して使う。親機は同じ URL を招待 URL（`/join`）にも使う。
- 既定値は CMake のキャッシュ変数 `VOCROZ_RENDEZVOUS_URL` でビルドに埋め込む。ホスティングが決まっていないため、ソースには置かない。
- 検証用に、起動引数 `--rendezvous-url=<URL>` で上書きできる（`docs/adr/0007-launch-interface.md` の引数の表に加える）。1 台の PC でローカルのランデブーサーバーを使った受け入れテストを、ビルドし直さずに行うため。

### コンポジションルートと閉じるときの確認（2026-11-09 追記）

- `remote-pa` のコンポジションルート（`apps/pa-desktop/src/composition_root`）は、両方のモードで共有するもの（データフォルダ、ログ、ダイアログの言語、埋め込んだ UI、JUCE のメッセージループ）を用意し、親機モード（`HostMode`）か子機モード（`client::make_client_app()`）を組み立てる。`client-desktop` は `pa-desktop` に依存できないので、共有するものは `ClientAppConfig` で渡す。
- ログはモードごとに別のファイル（`remote-pa-host`、`remote-pa-client`）、WebView2 のデータもモードごとに別のフォルダ（`webview2-host`、`webview2-client`）にする。同じデータフォルダで両方のモードを同時に動かしても、ファイルとブラウザープロセスを奪い合わないため。
- 子機モードの周期の処理（`ClientRuntime::poll()`）は、JUCE のタイマーで 10ms ごとに呼ぶ。音声の経路は周期を待たないので、制御の応答の遅れだけがこの間隔で決まる。
- ランデブーサーバーの URL がないか形が誤っていれば、子機は起動したうえで、招待の解決をつねに `UNREACHABLE` で返す（`UnavailableRendezvousClient`）。画面で理由を出せるようにし、起動そのものは止めない。
- エンジンへの接続の手順（`EngineAttacher`）では、1 回の手順でエンジンを起動するのは 1 回だけにする。接続が切れたら自動で 1 回だけ手順をやり直し、それでもつながらなければ「再試行」と「閉じる」を尋ねる。起動直後に落ちるエンジンを自動で起動し続けないため（`docs/adr/0008-runtime-behavior.md`）。ほかのユーザーのパイプやなりすまし（`ipc` の `kAccessDenied`、`kUntrustedServer`）では起動もせずに失敗にする。
- `pa-engine` はコンソールを作らずに起動する（`CREATE_NO_WINDOW`）。`remote-pa` はウィンドウのアプリ（Windows のサブシステム）にし、`--version` などの出力は親のコンソールがあるときだけそこへ出す。引数とパスを UTF-8 で受け取るため、アプリケーションマニフェストで `activeCodePage` を UTF-8 にする。
- 閉じるときの確認は、子機モードでは参加中（`ClientRuntime::in_session()`）、親機モードではセッションが `ACTIVE`（参加者がいる）のときだけ出す。親機の画面を閉じてもエンジンは止まらないが、本番中の誤操作を防ぐため、音が止まらないことを伝えたうえで確かめる。親機モードの判定は、エンジンから UI への中継をのぞく `SessionActivityTap` が、エンジンの送ったスナップショットと `session_updated` を読んで行う（状態を導き出さない）。
- 確認とエンジンの失敗のダイアログは Win32 のメッセージボックスで出す（既定のボタンは「キャンセル」）。WebView の外で出すので、文言は UI の文字列リソースではなく `apps/pa-desktop/src/dialog_text.cpp` に日本語と英語で持ち、`--lang` か OS の表示言語で選ぶ。

## 理由

- 子機モードのコントロールスレッドをメッセージスレッドにすると、UI からのメッセージをスレッドをまたがずに `session` へ渡せる。UI の描画は WebView2 の別プロセスで行われるので、メッセージスレッドが UI の描画で長く止まることはなく、止まってもオーディオスレッドと送信スレッドは動き続ける。
- 暗号化を送信スレッドにまとめると、`PacketSealer` を 1 つのスレッドだけで使う制約を守ったまま、オーディオスレッドからソケットの I/O をなくせる。エンコードはオーディオスレッドで行い、送信スレッドへは固定長のフレームだけを渡すので、送信スレッドの起床の遅れだけが追加の遅延になる。
- URL 1 つにまとめると、招待の HTTPS と UDP のランデブーが別のサーバーを指す設定の誤りが起きない。

## 結果

- 子機の送信の経路は、`tests/harness` の `MediaSender` と同じ部品の順序（エンコード → 暗号化 → 送信）を、スレッドを分けて製品に置いたものになる。結合テストの `SimulatedClient` は、コンポジションルートができたら `ClientRuntime` に置き換えられる。
- コンポジションルート（WebView、WASAPI、Winsock、WinHTTP）と親機モードは、`pa-engine`（#57）、`persistence`（#55）、`network` の招待の HTTPS の後に加えた。設定の保存とログは `persistence`、時刻は `common::SteadyClock` を使う。データフォルダの既定の規則は `pa-engine` と `pa-updater` と同じものを `remote-pa` の `src/win/known_paths` にも持つ（各アプリの `src/win/` に置く形に合わせた。共通化は定期リファクタリングで判断する）。
- 次の点は続きの作業にする。`remote-pa` の単一インスタンスと既存のウィンドウへの引数の受け渡し（`docs/adr/0007-launch-interface.md`）、エンジンが落ちたことの画面での知らせ方（今は再アタッチと、失敗したときのダイアログだけ）、子機の静的鍵の保存（今は起動ごとに作る）、親機モードの `--rendezvous-url` を `pa-engine` に渡すこと（今は `pa-engine` がビルド時の値だけを使う）。
- 送信スレッドの優先度（MMCSS への登録）は、実機での遅延の計測の後に決める。
