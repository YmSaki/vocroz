# 0018. ルーティンググラフのセンド、遅延ノード、複数の物理出力

- 状態: 採用（2026-11-08）

## コンテキスト

Beta1 では、入力、ユーザー作成のバス、Master、物理出力を自由に結線できるようにする（B1a）。
仕様書は次の 4 点を求めている。

- プリフェーダー / ポストフェーダーのセンドと、任意のセンドレベル。キュー / モニターバスの作成
- 意図しないフィードバックループ（発振経路）の検出と適用のブロック。ただし、明示的なディレイノードとオペレーターの承認がある場合は除く
- 入力ソースごとの手動ディレイ
- 複数バス / 複数物理出力

置き場所は ADR-0009 で決めた（グラフ、ループの検出、スワップは `audio-core`、ステージングと承認の判断は `session`）。
この ADR では、A1 の音声グラフ（`GraphDescription`）をどう拡張して上の 4 点を表すかを決める。
B4（VST3 の PDC）と B5（MIDI）はこのグラフの上に乗るので、ここで形を固める。

## 決定

### センド

- 結線（`Connection`）がセンドを表す。結線ごとに、送り元から取り出す位置（`SendTap::kPostFader` / `kPreFader`）と、センドレベル（`std::optional<FaderId>`）を持つ。
- センドレベルはフェーダーと同じ `FaderId` で表し、`Mixer` のフェーダー（ゲイン、ミュート、ゲインランプ）をそのまま使う。新しい種類のパラメーターを作らない。
- プリフェーダーの送り元はストリップとバスに限る。ストリップのプリフェーダーの位置は、手動ディレイの後、メーターとフェーダーの前。
- **プリフェーダーのセンドには必ずセンドレベルを付ける。** チャンネルのフェーダーの前から送るので、センドレベルがないと、新規参加者の音がチャンネルのミュートに関わらずキューに出てしまい、初期ミュートを守れない。フェーダーはミュートで始まるので、センドレベルを付ければ初期ミュートが守られる。
- キュー / モニターバスは、ノードの種類を増やさず、プリフェーダーのセンドを受けるバスとして表す。バスの役割の区別（表示名など）は `session` が持つ。

### フィードバックループ

- 新しいノードの種類 `kDelay`（ステレオの遅延ノード）を足す。遅延は 1 ブロック（128 サンプル）以上、2 秒以下。
- 遅延ノードの出力は、前のブロックまでに書いた入力から作る。遅延ノードへ入る結線は同じブロックの処理順を縛らないので、遅延ノードを通るループも処理順が決まる。遅延ノードの入力は、ブロックの最後にまとめて書き込む。
- ループの検出は、グラフの構造だけから決まる純粋関数 `analyze_feedback()` で行う。ループに含まれるノードと、遅延ノードを通らないループに含まれるノードを返す。ステージングとルーティング画面が、どのノードがループを作っているかを示すために使う。
- 遅延ノードを通らないループは、承認があっても適用できない（`GraphError::kCycle`）。遅延ノードを通るループは、`GraphDescription::feedback_approved` が true のときだけ適用できる（そうでなければ `kUnapprovedFeedback`）。承認するかどうかは `session` がオペレーターの操作から決める。
- グラフの検証は `Mixer::validate_graph()` で、適用せずに行える。`apply_graph()` と同じ規則を使う。

### 手動ディレイ

- 手動同期オフセットは、ストリップのパラメーター（`NodeSpec::delay_samples`、0〜1 秒）にする。独立したノードにはしない。オフセットは入力ごとの設定で、ノードとして結線を組み替える対象ではないため。
- ディレイの長さを変えるとグラフを作り直す（ディレイラインを確保し直す）。ディレイラインの中身は引き継がないので、変更の直後は遅延の長さだけ無音になる。手動オフセットは本番前に合わせる離散操作なので、この挙動で問題ないと判断した。

### 複数の物理出力

- 出力ノードを複数置けるようにし、出力ノードごとに出力デバイスのチャンネルの組の先頭（`NodeSpec::device_channel`）を持つ。L をそのチャンネル、R を次のチャンネルに書く。
- 複数の物理出力は、**1 台の出力デバイスの複数のチャンネルの組**として扱う。複数台の出力デバイスへの同時出力はこの ADR の範囲外とする。デバイスごとにクロックが異なり、デバイス間のドリフト補正が必要になるため。必要になったら、`device` と `pa-engine` の組み立て（E1）で別の ADR を書く。
- 2 つの出力ノードが同じチャンネルに書く構成は拒否する（`kOverlappingOutputs`）。後に書いた方だけが聞こえ、結線と出力が食い違うため。
- デバイスにないチャンネルへの出力は捨てる。別のチャンネルへ暗黙に振り替えない（AGENTS.md 1.2 のフェイルセーフ）。

## 理由

- センドを結線の属性にすれば、センドとバスへの入力が同じ 1 つの概念になり、マトリクス表示とノードグラフ表示のどちらからも同じ記述を作れる。
- 遅延ノードを経由したループだけを許せば、処理順をトポロジカル順のまま決められ、オーディオスレッドで反復計算や収束判定をせずに済む。遅延のないループは 1 サンプルの中で値が決まらず、ゲインが 1 を超えると即座に発振するので、承認の対象にもしない。
- 1 台のデバイスのチャンネルの組なら、すべての出力が同じコールバックで同じサンプル位置に書かれるので、複数バスの出力の整合性（サンプル単位でずれないこと）が構造上保証される。

## 結果

- `GraphError` から `kTooManyOutputs` をなくし、`kUnapprovedFeedback`、`kInvalidSendTap`、`kMissingSendLevel`、`kDelayOutOfRange`、`kOutputChannelOutOfRange`、`kOverlappingOutputs` を足す。
- センドレベルもフェーダーを 1 つ使うので、`MixerConfig::fader_capacity` はストリップ数 × センド先のバス数のぶんを見込んで決める（E1）。
- `session` のルーティングのステージング（仮の構成の保持、リビジョン、承認、`validate_graph()` による検証、`apply_graph()` による適用）は S1 の `session` モジュールの上に実装する。
- B4 は、プラグインノードを `NodeKind` に足し、報告されたレイテンシーから PDC の遅延を検証の段階（`plan_graph()`）で算出する。
