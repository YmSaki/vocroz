# 0002. Opus を低遅延モードで使う

- 状態: 採用（フレーム長とビットレートは P0 で実測して確定）

## 背景

用途は合奏で、低遅延が必須（2026-11-07 決定）。仕様の既定値（ジッターバッファ初期 60ms、WASAPI 共有モードのみ）では合奏に間に合わない。

## 決定

- 48kHz モノラル、`OPUS_APPLICATION_RESTRICTED_LOWDELAY`、フレーム長 2.5〜5ms。
- DTX は使わない（ミュート時の `PAUSED` / `NO_SIGNAL` 判定と紛らわしいため）。
- 低遅延モードではインバンド FEC が使えないので、欠損は PLC で補う。
- ジッターバッファは 10〜20ms 程度を既定にした「低遅延プロファイル」を用意し、上限と下限をオペレーターが選べるようにする。

## 影響

- 5ms フレームで毎秒 200 パケット / チャンネルになる。帯域と CPU 負荷を P0 で測る。
- 仕様 5.2（ジッターバッファ初期目標）と 5.4（WASAPI 共有モードのみ）は、低遅延プロファイル前提に改訂を提案する。
