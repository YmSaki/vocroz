# 0006. 招待 URL は HTTPS のリンクとし、アプリの起動にはユーザー単位の URL スキームを使う

- 状態: 採用（2026-11-07）

## コンテキスト

出演者は招待 URL を開くだけで子機モードの VOCROZ を起動できる必要がある。
ブラウザからネイティブアプリを起動するには、Windows では URL スキーム（プロトコルハンドラー）をレジストリに登録する必要がある。
一方で仕様書は、OS 環境を汚さないこと（ユーザー単位の導入、レジストリへの独自設定の保存をしない、アンインストール後にレジストリにゴミを残さない）を求めている。
アプリが入っていない出演者が招待 URL を開いた場合の導線も必要になる。

## 決定

- 招待 URL は `https://<ランデブーサーバー>/join#<招待コード>` の形の HTTPS のリンクにする。招待コードは URL のフラグメント（`#` 以降）に入れ、HTTP リクエストとしてサーバーに送られないようにする。
- `/join` は静的なページで、次の 3 つだけを表示する。
    - 「VOCROZ で開く」ボタン（`vocroz://join?code=<招待コード>` へのリンク。ページの JavaScript がフラグメントから組み立てる）
    - アプリが入っていない場合のダウンロードへのリンク
    - 招待コードと、アプリに貼り付けるためのコピーボタン
- URL スキーム `vocroz` は、インストーラー（WiX）が `HKCU\Software\Classes\vocroz` にだけ登録し、アンインストーラーが削除する。管理者権限は使わず、`HKLM` には書かない。アプリ自身は実行時にレジストリへ書き込まない。
- 登録するのは URL スキームの関連付けだけで、設定値はレジストリに保存しない（設定は従来どおり `%LOCALAPPDATA%` 配下のファイル）。
- `vocroz://` で渡された引数は信頼できない外部入力として扱う。受け付けるのは `join` と招待コードだけで、それ以外は無視する。招待コードの形式の検証は `session` が行う。
- URL スキームで起動しても、自動では参加しない。子機モードの「招待の確認」画面を開き、出演者がマイクを選んで参加を申請するまで、何も送信しない（音声は従来どおり親機の承認まで流れない）。
- 子機モードがすでに起動していれば、新しいプロセスは引数を既存のプロセスへ渡して終了する（名前付きミューテックスと名前付きパイプによる単一インスタンス化）。
- アプリの画面には、招待 URL か招待コードを貼り付けて参加する入口も常に用意する。URL スキームが使えない環境（ブラウザがブロックする、関連付けが壊れている）でも参加できるようにするため。

## 理由

- URL スキームの登録は Zoom、Discord、Slack などの会議や通話のアプリが一般的に行っていることで、出演者にとって自然な体験になる。ブラウザも起動の前に確認を出すので、利用者の知らないうちにアプリが動くことはない。
- `HKCU\Software\Classes` への登録はユーザー単位で、管理者権限が不要で、アンインストーラーが確実に削除できる。仕様書が禁じている「独自設定のレジストリ保存」「PATH の書き換え」「シェル拡張」「常駐」には当たらない。
- 招待コードをフラグメントに入れると、ランデブーサーバーのアクセスログに招待トークンが残らない。
- HTTPS のリンクにしておけば、アプリが入っていない出演者もダウンロードまで迷わずにたどり着ける。

## 結果

- インストーラー（P5）で URL スキームの登録と削除を行う。アンインストールの受け入れテストでは、`HKCU\Software\Classes\vocroz` が残っていないことも確かめる。
- ランデブーサーバーの製品サイトに `/join` の静的ページを追加する（`infra/rendezvous`）。
- 招待 URL と `vocroz://` の引数のパースは `session` に置き、`remote-pa` のエントリポイントは引数を `session` に渡すだけにする。
- 単一インスタンス化と引数の受け渡しは `remote-pa` のアダプター（`apps/pa-desktop/src/win/`）で行う。
