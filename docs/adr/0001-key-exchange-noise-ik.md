# 0001. 鍵交換に Noise_IK を使う

- 状態: 採用（2026-11-07）

## 背景

仕様書は、メディアと制御のすべてのパケットを AEAD で保護し、鍵交換方式を Noise か DTLS 1.3 から選ぶよう求めている。招待トークンには親機の公開鍵指紋が入るため、子機は接続前に親機の静的公開鍵を知っている。

## 決定

- Noise プロトコルの `Noise_IK_25519_ChaChaPoly_BLAKE2s` を使う。
- 実装は既存ライブラリ（noise-c 等）と libsodium を使い、暗号プリミティブは自作しない。
- ハンドシェイク後は独自 UDP フレームのヘッダー（版、接続ID、種別、シーケンス番号）を AEAD の関連データにし、シーケンス番号でリプレイを排除する。

## 理由

- IK パターンは「開始側が応答側の静的鍵を事前に知っている」前提で、招待トークンの公開鍵指紋とそのまま一致する。
- DTLS 1.3 より実装範囲が小さく、独自 UDP フレームに組み込みやすい。

## 影響

- 短い招待コードはランデブーサーバー経由で公開鍵を受け取るため、サーバーへの信頼が前提になる。Alpha では確認記号（SAS）を作らず、招待 URL を推奨経路にする。
- RC1 前に外部のセキュリティレビューを受ける。
