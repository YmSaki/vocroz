# 0021. UDP ソケット、NAT 越えの手順、自動ポート開放

- 状態: 採用（2026-11-08）

## コンテキスト

仕様書は、接続を「直結（IPv6 のグローバルアドレス、手動のポート転送、UPnP-IGD / NAT-PMP / PCP による自動ポート開放）」→「UDP ホールパンチング」の順で試し、どちらも成立しなければ「接続済み」と表示せず原因別のエラーを返すよう求めている。
ランデブーサーバーのプロトコル（REGISTER、REGISTERED、PUNCH）は ADR-0012 で決まり、パケットの形式と暗号化は ADR-0014 で、ファイアウォールの規則を追加しないことは ADR-0008 で決まっている。
決まっていないのは、ソケットを何本持つか、直結とホールパンチをどう組み合わせるか、ホールパンチで何を送るか、自動ポート開放をどう実装するか（ライブラリを使うか）の 4 点だった。

## 決定

### ソケット

- 親機と子機は、それぞれ UDP ソケットを 1 本だけ持つ。`AF_INET6` で `IPV6_V6ONLY` を 0 にしたデュアルスタックのソケットで、IPv4 の相手には IPv4 射影アドレス（`::ffff:a.b.c.d`）で送る。IPv6 のソケットを作れない環境では IPv4 だけのソケットに切り替える。
- ランデブーサーバーへの REGISTER、ホールパンチ、相手とのメディアと制御は、すべてこの 1 本で送受信する。受信したデータグラムは、先頭が `VRZ` ならランデブーメッセージ、それ以外は相手のパケットとして振り分ける（`ReceiveRouter`）。
- 受信はネットワーク受信スレッドが `WSAEventSelect` のイベントで待つ。停止用のイベントで待ちを解くので、ソケットを別スレッドから閉じて受信を中断させる必要がない。送信は非ブロッキングで、送れなければ捨てる（UDP なので、失われたパケットと同じに扱う）。
- 相手の到達不能を知らせる ICMP で以降の受信が失敗しないよう、`SIO_UDP_CONNRESET` を無効にする。他のプロセスに同じポートを奪われないよう、`SO_EXCLUSIVEADDRUSE` を付ける。

### NAT 越えの手順

- 子機は親機と同じランデブー ID で REGISTER を 1 秒ごとに送り、親機は 10 秒ごとに送る（初回の REGISTERED が届くまでは親機も 1 秒ごと）。REGISTER にはローカルの候補アドレスを最大 8 個入れる。順序は、自動ポート開放で得た外部アドレス、IPv6 のグローバルアドレス、IPv4 のアドレス、IPv6 のユニークローカルアドレスの順にする。ループバック、リンクローカル、マルチキャスト、Teredo は入れない。
- 直結とホールパンチを別々の段階にせず、PUNCH で受け取ったすべての候補（相手のサーバー再帰アドレスと、相手が申告した候補）へ同時に送る。直結できる候補（ポート開放済みの外部アドレス、IPv6 のグローバルアドレス、同じ LAN のアドレス）があれば最初に応答が返るのでそちらが使われ、なければサーバー再帰アドレスへのホールパンチで開通する。
- 子機は Noise_IK の 1 つ目のメッセージをそのまま全候補へ送る。親機は空のデータグラムを相手の全候補へ送り、自分の側の NAT のマッピングを開く。50ms 間隔で、最後の PUNCH から 5 秒間送り続ける。最初に認証済みの応答を返した送信元を、以降の送信先にする（`PeerDatagramSocket`）。
- 子機は試行の開始から 10 秒で打ち切り、原因を次の順に判定して返す。REGISTERED が一度も届かなければ `kRendezvousUnreachable`、PUNCH が一度も届かなければ（親機が登録していない）`kHostNotFound`、PUNCH は届いたが鍵交換まで進まなければ `kUnreachable`。サーバーが上限で登録を断ったら、その時点で `kRendezvousCapacity` を返す。session はこれらを `UNREACHABLE` として表示し、原因に応じた対処案を出す。
- REGISTERED と PUNCH は、ランデブーサーバーのアドレスから届き、自分の REGISTER のトランザクション ID（PUNCH は 0 も可）とランデブー ID が一致するものだけを受け付ける。

### 自動ポート開放

- 親機はセッションの作成時に、PCP（RFC 6887）→ NAT-PMP（RFC 6886）→ UPnP-IGD の順でポート開放を試み、最初に成功した方法で得た外部アドレスを候補の先頭に入れる。どれも成功しなければ、候補なしのまま進める（ホールパンチで接続できるため、エラーにはしない）。
- PCP と NAT-PMP は自前で実装する。どちらもデフォルトゲートウェイの UDP 5351 番への 1 往復で、メッセージは固定長のバイナリなので、パーサーを `src/wire/` に置いて単体テストする。PCP を先に送り、ゲートウェイが NAT-PMP のバージョンで応答したら NAT-PMP に切り替える。再送は 250ms から倍にして 3 回までにし、1 つの方法で待つのは最大 1.75 秒にする。
- UPnP-IGD には miniupnpc（2.3.3、BSD-3-Clause）を使う。SSDP による探索、デバイス記述の XML の解析、SOAP の呼び出しまでを自前で書くと量が多く、ルーターごとの差異への対応も積み重ねになるため。miniupnpc は Windows のビルドだけで取得し、使ってよい範囲は `network` だけにする。
- ゲートウェイがプライベートアドレスしか持たない（二重 NAT）場合、UPnP のポート開放は外から届かないので、成功として扱わない。
- 割り当ての寿命は 1 時間で、使う側が寿命の半分で更新する。セッションの終了時に削除する。

## 理由

- ソケットを 1 本にしないと、ランデブーサーバーが見た外部アドレスと、相手と通信するときの外部アドレスが一致しない。ホールパンチはこの一致が前提なので、ランデブーサーバーとの通信も相手との通信も同じソケットで行う。
- 直結を先に試してからホールパンチに進むと、直結できない環境（大半の家庭の回線）で直結の待ち時間がそのまま接続時間に加わる。すべての候補へ同時に送れば、直結できる環境では直結が、できない環境ではホールパンチが、どちらも待ち時間なしで成立する。仕様の試行順は、候補の並び順（直結の候補を先にする）で保つ。
- 子機が送るのを鍵交換のメッセージにすれば、届いた経路でそのまま鍵交換が始まり、経路の確認のための往復を別に持たずに済む。親機は子機より先に鍵交換のメッセージを送れないので、マッピングを開くだけの空のデータグラムを送る。空のデータグラムは transport が固定ヘッダーより短いものとして捨てるので、相手の状態に影響しない。
- STUN の Binding は実装しない。REGISTERED がサーバーから見た外部アドレスを返し、PUNCH にも入っているので、同じ情報を別のメッセージで取る必要がない（AGENTS.md 1.2 のシンプルさ）。NAT の種類の判定などで必要になったら追加する。
- PCP と NAT-PMP はメッセージが固定長で単純なので、ライブラリを入れるより自前のほうが依存も攻撃面も小さい。UPnP-IGD は XML と HTTP を含むので、実績のあるライブラリに任せる。
- miniupnpc は BSD-3-Clause で、AGPL-3.0 の配布物に含められる。Transmission など多くのアプリケーションで使われていて、Windows を含む主要なプラットフォームでビルドできる。

## 結果

- `modules/network` を作る（責務は AGENTS.md 3.3 の表のとおり）。Linux ではプラットフォームに依存しない部分（振り分け、ランデブーの手順、ホールパンチ、PCP と NAT-PMP の手順、パーサー）だけをビルドしてテストし、Winsock と miniupnpc を使うアダプターは Windows だけでビルドする。
- AGENTS.md 4.2 の外部ライブラリの表に miniupnpc（`network`）を、CONTRIBUTING.md のライセンスの表に miniupnpc を追加する。miniupnpc のアダプターは Windows のビルドでだけ使うので、`src/win/` に置く。
- 対称型 NAT 同士など、ホールパンチが成立しない組み合わせは `kUnreachable` になる。中継は提供しない（仕様のとおり）。
- 親機の受信スレッドは同じ鍵交換のメッセージを複数の経路から受け取ることがある。親機の組み立て（E1）は、接続 ID が同じ 2 つ目以降のメッセージを重複として扱う。
- 招待の HTTPS（`session` の `RendezvousClient` の実装）は、`session` のマージ後に同じモジュールへ追加する。
- QoS（DSCP）の設定は、Windows では管理者権限か qWAVE が必要になるので、この ADR では扱わない。
