# 0041. プラグインのエディターのウィンドウと、プラグインの失敗の知らせ方

- 状態: 採用（2026-11-09）

## コンテキスト

ADR-0024 で、処理が失敗したプラグインと NaN を出したプラグインのノードを無音にすることを決めた。
ADR-0032 で、スキャン中に落ちた、止まったファイルを読み込み不可として記録することを決めた。
どちらも、オペレーターに知らせる経路は決めていない。
ADR-0032 では、エディターのウィンドウ（`PluginEditorHost`）も続く PR に残した。

仕様の要求は次のとおり。

- VST の独自のエディターは、独立したネイティブウィンドウとして開く。閉じても音声処理は続く。
- プラグインがハングアップかクラッシュしたら、そのパスだけを安全にバイパスかミュートし、セッションを続ける。

現在の実装には、次の 2 つの問題がある。

- 無音にしたことはグラフの中（オーディオスレッドだけが読み書きする値）にしかなく、コントロールスレッドから読めない。
- この値はグラフを構築し直すと消える。ほかの変更（フェーダーの結線の変更など）でグラフを差し替えると、NaN を出したプラグインの処理が再開してしまう。

`pa-engine` には、JUCE のメッセージスレッドが専用に 1 本ある（ADR-0039）。エディターのウィンドウもこのスレッドで扱う。

## 決定

### 失敗の印

- `audio-core` に、プラグインノードの失敗の印 `PluginFault` を置く。
  - オーディオスレッドが立て（`raise()`）、どのスレッドからでも読める（`raised()`）。
  - 一度立てたら下ろさない。
- `NodeSpec::make_plugin()` に、印を `std::shared_ptr` で渡せるようにする。印は任意で、渡さなければ従来どおりグラフの中だけで持つ。
- 印を渡したノードは、次のように振る舞う。
  - 処理が失敗するか NaN を出したら、印を立てる。
  - グラフを構築した時点で印が立っていれば、最初から無音にし、プラグインを呼ばない。
- 印は、プラグインを読み込むたびに新しく作る。プラグインを読み込み直すまで、無音のままにする。

### 失敗の知らせ方

- 失敗は、一度だけのイベントではなく、状態として `session` に持つ。
  - UI（`remote-pa`）が落ちて再接続したとき、スナップショットで失敗が分かるようにするため。
  - 状態が変わったときに、差分のイベントを送る。UI はイベントを受けたら、非モーダルのトースト通知を出す。
- 処理の失敗: コントロールスレッドが、挿したプラグインの `PluginFault` を周期の処理で見る。新しく立った印を、そのプラグインの失敗の状態にする。
- スキャンの失敗: `PluginCatalog` の読み込み不可の記録（落ちた、止まった、出力が壊れていた）を、スキャンが終わったときに一覧として UI に渡す。
- 失敗を解く操作は、プラグインの読み込み直し（外して挿し直す）だけにする。
  - 失敗したプラグインの状態は分からない。処理を黙って再開すると、壊れた音が突然戻るおそれがあるため。
- control-protocol のコマンドとイベントの形は、プラグインの挿入を `session` に加える PR で決める。挿入の状態がまだないためである。

### エディターのウィンドウ

- `session` に `PluginEditorHost` のポートを置く。
  - `open(instance, title)`: エディターを開く。開いていれば、そのウィンドウを前面に出す。
  - `close(instance)`: エディターを閉じる。
  - `is_open(instance)`: エディターが開いているか。
  - `close_all()`: すべて閉じる。
- `plugin-host` が、JUCE の `DocumentWindow` で実装する（`make_juce_plugin_editor_host()`）。
  - ウィンドウはインスタンスごとに 1 つまで開く。
  - 独自の画面を持たないプラグインは、パラメーターの一覧（`GenericAudioProcessorEditor`）で代える。画面が開かないより、パラメーターだけでも操作できる方がよいため。
  - エディターを作る途中でプラグインが例外を送出したら、`kOpenFailed` を返す。プラグインの処理は続ける。
  - `PluginLoader` 以外で作ったインスタンスには `kNotSupported` を返す。
- ウィンドウはエディターを表示するだけで、グラフのノードには触れない。閉じても音声は続く。
- すべての呼び出しと破棄は、JUCE のメッセージスレッドで行う（ADR-0039）。
  - コントロールスレッドから開閉するときは、`JuceMessageThread::post()` で渡す。
  - 結果（開けなかった）は、コントロールスレッドのキューへ戻す。
- オペレーターが閉じるボタンを押したら、ウィンドウを隠し、`is_open()` をすぐ false にする。ウィンドウの破棄は、メッセージスレッドに積んで後で行う。閉じるボタンのコールバックは、ウィンドウの中から呼ばれるためである。
- 寿命:
  - `session` は、インスタンスを破棄する前に `close()` を呼ぶ。エディターはプラグインを参照しているため。
  - そのうえでウィンドウもプラグインの処理（`JucePluginProcessor`）を `std::shared_ptr` で持ち、エディターより先にプラグインが破棄されないようにする。取り決めが守られなかったときに、破棄済みのプラグインをエディターが参照しないようにするためである。
  - `pa-engine` の終了時は、ADR-0039 の順序に従い、メッセージスレッドの最後の処理で `close_all()` を呼んでから JUCE を終える。

## 理由

- **フェイルセーフ**: 失敗したプラグインを黙って再開させない。印をグラフの外に置けば、グラフを差し替えても無音を保てる。
- **低遅延**: 印は `std::atomic<bool>` 1 つで、オーディオスレッドはブロックもヒープの確保もしない。コントロールスレッドは周期の処理で読むだけなので、オーディオスレッドからのキューを増やさない。
- **状態として持つ**: エンジン主権（AGENTS.md 1.1）に合わせ、UI は状態を導出しない。再接続した UI にも同じ失敗を見せられる。
- **ウィンドウはプラグインの寿命に合わせる**: VST3 のエディターは、プラグインより先に破棄する必要がある。ウィンドウがプラグインを持てば、破棄の順序をウィンドウの中で保証できる。

## 結果

- グラフを差し替えても、印を渡したプラグインのノードは無音のまま変わらない。印を渡さない従来の使い方では、振る舞いは変わらない。
- `pa-engine` への組み込み（プラグインの挿入、印の監視、エディターの開閉のコマンド、UI の表示）は、続く PR で行う。プラグインの挿入の状態は、まだ `session` にない。
- アウトオブプロセスの実行（クラッシュの隔離）は、引き続き余力次第とする。インプロセスでは、プラグインが本当にクラッシュするとエンジンごと落ちる。
